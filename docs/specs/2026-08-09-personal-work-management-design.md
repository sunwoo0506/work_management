## 1. 무엇을 만드는가

제우스 경영지원 업무를 혼자 관리하는 개인용 웹 서비스. 아침에 열어 하루 종일 켜두고, 퇴근 전에 기록하고, 주 단위로 계획하고, 보고할 때 자료를 뽑는 도구다.

### 1.1 해결하려는 문제

인수인계로 시작해 대표 지시사항(사업이해자료 §9의 7가지 등)이 실제 업무로 전개되는데, 그 사이를 이어줄 도구가 없다. 어제 어디서 멈췄는지, 오늘 뭘 해야 하는지, 누구에게 뭘 요청했고 회신을 받았는지가 흩어진다.

### 1.2 비목표

- **숫자 집계를 하지 않는다.** 축별 손익·재고·현금 집계는 별도 경영관리 앱의 몫이며 `PRD_경영관리서비스.md`에 이미 정의되어 있다. 이 서비스는 "그 숫자를 만드는 일"만 관리한다.
- 개인 생활 영역(습관·재정·여행 등)을 다루지 않는다.
- 다른 사람과 공유하거나 협업하지 않는다. 단독 사용 전제다.
- 이카운트·위하고와 연동하지 않는다.

## 3. 메뉴 구조

사이드바 5탭. 하루 종일 켜두는 도구라 사이드바가 짧을수록 시선이 덜 분산된다.

```
[업체 셀렉터]        ← 업체가 2개 이상일 때만 표시

빠른 입력
  ＋ 새 업무   ＋ 회의록   ＋ 전화메모

메뉴
  📌 오늘
  📋 업무          담당·요청 통합 (출처로 구분)
  🗓 계획          주간 · 월간 · 마일스톤
  ✏️ 기록          업무일지 · 회의록 · 전화메모
  📖 기준          지시사항 · 인수인계 · 연락처 · 업체 · 설정

오늘 한눈에
  할 일 n · 지연 n · 회신 대기 n · 인박스 n
```

### 3.1 「오늘」 화면

블록 순서가 곧 하루의 순서다.

| 블록 | 내용 |
|---|---|
| **어제 이야기** | 전날 일지의 「이슈·막힌 것」, 전날 완료한 업무, 일지에서 업무로 올리지 않은 메모 |
| **오늘 할 일** | 체크 목록. 어제 일지의 「내일 할 일」 중 체크한 것 + 오늘 기한 도래 업무 + 오늘 하기로 찍은 업무 |
| **진행 중 업무** | 지시사항 단위 묶음. 타임라인 뷰(기본) / 목록 뷰 전환. 시작일·마감일·D-day·진행률·업무 건수 |
| **인박스** | 맨 하단. 분류 전 메모 |
| 우측 — **이번 주** | 정기 미팅과 마감(회생 제출 등) |
| 우측 — **반복업무** | 매일·매주 빠지면 안 되는 것 |

마일스톤 블록은 두지 않는다. 진행 중 업무가 그 역할을 대신한다.

### 3.2 나머지 화면

**업무** — 목록 뷰 / 칸반 뷰. 「출처」로 *내 발의* / *요청받음* 구분. 요청받은 건에만 요청자·부서·접수경로·회신기한·회신내용이 붙고, 회신을 해야 닫힌다. 업무 상세에 체크리스트·지시사항 연결·기간.

**계획** — 주간(이번 주 목표, 요일별 배치, 회고) / 월간(이달 목표, 주차별 덩어리, 고정 일정) / 마일스톤(여러 지시사항을 아우르는 관문).

**기록** — 업무일지(§4.1) / 회의록(§4.3) / 전화메모.

**기준** — 지시사항(제우스는 사업이해자료에서 도출한 D-01~D-13) / 인수인계 / 연락처 / 업체 관리 / 설정(업무영역 분류, 사내 용어집). **이 다섯은 전부 업체별로 갈린다.**

## 4. 핵심 동작

### 4.1 업무일지 — 하루를 잇는 이음새

일지는 기록이 아니라 어제와 오늘을 잇는 장치다. 4단 구성이다.

| 섹션 | 입력 | 동작 |
|---|---|---|
| **1. 오늘 진행한 업무** | 자동 수집 | 그날 상태가 바뀐 업무와 체크한 항목을 모아 **스냅샷으로 굳힌다**. 나중에 업무를 수정해도 그날 일지는 바뀌지 않는다 |
| **2. 이슈 · 막힌 것** | 직접 | 다음날 「어제 이야기」에 올라온다 |
| **3. 내일 할 일** | 직접 | 줄마다 **「업무로」 체크박스**. 체크한 것만 업무로 등록(기한=내일)되어 다음날 「오늘 할 일」에 나타난다. 체크 안 한 것은 다음날 「어제 이야기」에 *메모로 남긴 것*으로 표시된다 |
| **4. 메모** | 직접 | — |

업체가 여럿이면 일지 한 장 안에서 업체별 섹션으로 나뉜다. 업체가 하나면 섹션 헤더 없이 지금처럼 보인다.

### 4.2 인박스 — 모든 것이 업무가 되는 깔때기

```
회의록에서 추출된 할 일 ┐
전화메모의 「조치할 것」  ├→ 인박스 →→ 업무로 승격 (기한·중요도 지정)
직접 던져둔 메모        ┘              또는 버림
```

### 4.3 녹음 → 회의록

```
폰/PC에서 업로드 → Supabase Storage (status: 대기)
      ↓  로컬 워커가 감지 (Realtime 구독, 실패 시 30초 폴링으로 폴백)
  Whisper large-v3 전사 (내 PC GPU) → transcript 저장 → 음성 파일 삭제
      ↓
  Edge Function → Claude → 회의록 초안 + 할 일 추출
      ↓
  회의록 저장 · 할 일은 인박스로 · 프론트는 Realtime으로 진행률 표시
```

**사내 용어 교정** — 전사가 「타이백」으로 나와도 회의록에는 「타이벡」으로 적힌다. 타이벡·유공타이벡·마더롤·슬리팅·원지정비·승급률·이카운트·위하고 등을 용어집으로 Claude에 함께 넘긴다. 용어집은 「기준 › 설정」에서 관리한다.

**민감 회의 정책** — 업로드 시 「민감」으로 표시하면
1. 전사 후 음성 파일 즉시 삭제
2. Claude 자동요약을 하지 않음
3. **전사문을 Supabase에 저장하지 않고 로컬 PC에만 둔다.** 클라우드에는 제목·일시·참석자만 남는다

회생·인사 회의용이다. 그 회의록 본문은 노트북·폰에서 볼 수 없다 — 자료 성격상 의도된 제약이다.

**PC가 꺼져 있으면** 전사가 대기 상태로 쌓인다. 켜면 밀린 것부터 처리한다. 나머지 기능은 PC와 무관하게 동작한다.

### 4.4 업체 확장

사업체가 5개까지 늘어날 수 있다. 지금 대비해 둔다.

- 모든 테이블에 `company_id`
- **업체가 1개면 셀렉터를 숨긴다** — 지금 화면은 단일 업체와 동일하게 보인다
- 2개째를 등록하면 사이드바 상단에 셀렉터가 나타난다
- 「오늘 할 일」은 기본 **전 업체 통합**, 업체 뱃지로 구분. 셀렉터로 한 업체만 필터
- 업무일지는 통합하되 일지 안에서 업체별 섹션으로 구분
- 지시사항·인수인계·연락처·업무영역·반복업무는 업체별로 완전히 분리

## 5. 데이터 모델

19개 테이블. 전부 `company_id`와 `user_id`(RLS용)를 가진다.

| 테이블 | 핵심 필드 |
|---|---|
| `companies` | 이름, 색, 활성, 정렬순서 |

| `tasks` | 제목, 상세, **출처**(내 발의/요청받음/일지/인박스/회의록), 요청자·부서·경로·회신, 지시사항ID, 영역, 중요도, 상태, 시작일, 기한, **focus_date**, 진행률 |
| `checklist` | 업무ID, 항목, 필수여부, 완료 |
| `inbox` | 내용, 태그, 출처(직접/회의록/전화메모), 원본ID, 승격된 업무ID |
| `daily_logs` | (업체, 날짜) 유니크, 자동수집 스냅샷(JSON), 이슈, 메모, 투입시간 |
| `log_todos` | 일지ID, 제목, 중요도, **업무로 올림 여부**, 승격된 업무ID |
| `meetings` | 일자, 제목, 장소, 참석자, 안건, 결정사항, 후속조치, 녹음ID, 민감여부 |
| `recordings` | 파일경로, 길이, 상태(대기/전사중/전사완료/요약완료/실패), 진행률, 전사문, 민감여부, 오류 |
| `calls` | 통화시각, 상대, 소속, 연락처, 수신/발신, 내용, 조치, 처리여부 |
| `plans` | 종류(주간/월간), 기간, 목표(JSON), 메모, 회고 |
| `milestones` | 이름, 구분, 시작일, 목표일, 완료조건, 상태 |
| `events` | 제목, 종류(정기미팅/마감), 시각, 반복규칙, 종료일 |
| `routines` | 제목, 주기(일/주/월), 요일, 일자, 활성 |
| `routine_checks` | 반복업무ID, 날짜, 완료 |
| `handover` | 분류, 항목, 상대, 물어볼 것, 상태, 기한, 메모 |

| `settings` | 업체별 키-값 (업무영역 목록, 사내 용어집) |
| `activity` | 대상, 동작, 내용, 시각 |

### 5.1 파생 규칙

- **오늘 할 일** = `due_date = 오늘` **또는** `focus_date = 오늘`, 상태 ≠ 완료
- **어제 이야기** = 전날 `daily_logs.issues` + 전날 완료된 `tasks` + 전날 `log_todos` 중 미체크 항목
- **진행 중 업무** = 상태가 완료·보류가 아닌 `tasks`를 `directive_id`로 묶고, 묶음의 시작일=최소 시작일 / 마감일=최대 기한 / 진행률=평균

## 6. 기술 구조

```
Work_Management/
  frontend/          React · Vite · TypeScript · Tailwind  → Vercel
    src/pages/       Today  Work  Plan  Record  Base
    src/components/  tiles  cards  kanban  calendar  timeline
    src/lib/         supabase.ts  types.ts(자동생성)  queries/
  supabase/
    migrations/      스키마 + RLS 정책
    functions/       summarize — Claude 호출
  worker/            로컬 전사 워커 (Python)
    transcribe_worker.py
  docs/specs/
```

| 영역 | 선택 | 이유 |
|---|---|---|
| 프론트 | React + Vite + TS + Tailwind | 사용자가 이미 쓰던 스택 |
| 서버 상태 | TanStack Query + Supabase Realtime | 낙관적 업데이트로 클릭이 즉시 반영 |
| DB·인증·저장소 | Supabase (Postgres + Auth + Storage) | 무료 티어로 충분, 어디서나 접근 |
| 요약 | Edge Function → `claude-opus-5` | API 키가 브라우저에 노출되지 않음 |
| 전사 | 로컬 워커 + faster-whisper `large-v3` (CUDA) | RTX 3060 6GB. 1시간 → 2~5분. 음성이 PC를 벗어나지 않음 |
| 칸반 | dnd-kit | 드래그앤드롭 |
| 차트 | Recharts | 진행바·타임라인 |
| 배포 | Vercel | 무료 |

**인증** — Supabase Auth의 이메일 매직링크. 단독 사용이라 비밀번호 관리를 하지 않는다. 로컬 워커는 `service_role` 키가 아니라 전용 계정 토큰으로 붙는다(`.env`, git 제외).

## 7. 수용 기준

- [ ] 일지의 「내일 할 일」에서 체크한 항목만 다음날 「오늘 할 일」에 나타난다. 체크 안 한 항목은 「어제 이야기」에 메모로 표시된다
- [ ] 전날 일지의 「이슈·막힌 것」이 다음날 「어제 이야기」에 그대로 올라온다
- [ ] 「오늘 진행한 업무」는 스냅샷이라 이후 업무를 수정해도 변하지 않는다
- [ ] 회의록·전화메모에서 추출된 할 일이 인박스에 들어가고, 인박스에서 업무로 승격된다
- [ ] 요청받은 업무는 회신 내용을 기록해야 닫힌다
- [ ] 진행 중 업무가 지시사항 단위로 묶여 시작일·마감일·D-day·진행률과 함께 타임라인으로 보인다
- [ ] 폰에서 녹음 파일을 올리면 PC 워커가 전사하고 회의록 초안이 생성된다
- [ ] 「민감」 표시한 회의는 전사문이 Supabase에 저장되지 않고 음성이 삭제된다
- [ ] 사내 용어가 회의록에서 올바르게 교정된다
- [ ] 업체가 1개일 때 셀렉터가 보이지 않고, 2개째 등록 시 나타난다
- [ ] 반복업무가 주기에 맞게 매일 생성되고 체크할 수 있다
- [ ] 본인 데이터만 조회된다 (RLS)

## 8. 위험과 대응

| 위험 | 대응 |
|---|---|
| GPU 전사 환경(CUDA·cuDNN·ffmpeg) 설치가 까다롭다 | CPU 모드(`medium`, 1시간 → 8~15분)로 자동 폴백. 워커가 죽어도 앱 나머지는 정상 동작하도록 분리 |
| PC가 꺼져 있으면 전사가 대기 | 의도된 동작. 켜면 밀린 것부터 처리. 대기 건수를 화면에 표시 |
| Supabase 무료 티어는 1주일 미접속 시 일시정지 | 매일 사용이 전제라 실무상 문제 없음. 재개는 대시보드 버튼 |
| Storage 무료 1GB (1시간 녹음 = 30~60MB) | 전사 완료 후 음성 파일 자동 삭제 |
| 업무 데이터가 외부 클라우드에 저장됨 | 회사가 이미 이카운트·위하고 등 외부 SaaS 사용 중. 민감 회의는 §4.3 정책으로 분리 |
| 사업이해자료(사외 반출 금지)의 유출 | 저장소 루트를 `Work_Management/`로 한정해 원본 문서가 git 바깥에 있음 |
| 날짜 경계 로직 오류 (일지→업무, 반복업무, 주·월 경계) | 해당 로직에 테스트 필수 |

## 9. 검증 방법

- Supabase 마이그레이션은 SQL 파일로 버전 관리, 로컬 `supabase start`로 검증
- **일지→업무 승격 / 반복업무 생성 / 주·월 경계** 로직은 Vitest로 단위 테스트 (날짜 경계 케이스 포함)
- RLS 정책 테스트 — 다른 사용자 데이터가 조회되지 않는지
- `openapi-typescript`(또는 `supabase gen types`)로 DB 타입을 자동 생성해 계약 불일치를 컴파일 단계에서 차단
- 워커는 pytest + 목(mock). 실제 Whisper·Claude 호출 없이 상태 전이 검증

## 11. 구현 순서

한 번에 다 만들지 않는다. 각 단계가 끝나면 그 시점부터 실제로 쓸 수 있어야 한다.

| 단계 | 범위 | 끝나면 할 수 있는 것 |
|---|---|---|
| **1. 뼈대와 업무** | Supabase 스키마 + RLS, 인증, 5탭 껍데기, 애플 디자인 토큰, 업무 CRUD·목록·칸반, 지시사항, **인박스**, 시드 | 떠오른 걸 인박스에 던져두고, 업무로 승격해 칸반으로 옮길 수 있다 |
| **2. 하루의 흐름** | 「오늘」 화면 전체, 업무일지 4단, 일지→업무 승격, 어제 이야기, 반복업무 | 아침에 열고 퇴근 전 기록하는 사이클이 완성된다 |
| **3. 계획과 기준** | 주간·월간 계획, 마일스톤, 정기일정, 인수인계·연락처·업체·설정 | 주 단위 계획과 보고 자료 추출이 된다 |
| **4. 녹음** | Storage 업로드, 로컬 전사 워커, Edge Function 요약, 용어집 교정, 민감 회의 정책 | 폰 녹음이 회의록이 된다 |

1단계의 인박스는 **직접 던져둔 메모**만 받는다. 회의록·전화메모에서 인박스로 흘러드는 경로(§4.2)는 각각 3·4단계에서 붙는다.

**업체 셀렉터 UI는 4단계 이후** 또는 실제로 두 번째 업체가 생길 때 붙인다. `company_id`는 1단계부터 모든 테이블에 넣되 화면에는 노출하지 않는다.
