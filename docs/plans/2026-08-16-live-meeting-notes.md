# 실시간 회의록 — 기획

> 회의 중에 툴이 옆에서 듣고, 끝나면 회의록 초안이 나와 있게 한다.
> 노션에 있는 그 기능을 이 툴에 붙이는 이야기다.

작성 2026-08-16 · 관련 문서: 설계서 §5.8 · §14 OQ-14 · 확인메모 C-06 · 회고 `2026-08-10_v02` 이슈 4-4

> ⚠️ **같은 날 뒤집힌 결정이 하나 있습니다 (결-3).**
> 이 문서 곳곳의 *"민감 회의는 잠근다"* 는 **더 이상 유효하지 않습니다.**
> 사용자 판단으로 **민감 회의도 일반 회의와 같은 길로 갑니다** — 「민감」은 표시로만 남습니다.
> 아래 본문은 **그때 그렇게 판단한 기록**으로 남겨 둡니다. 경위는 §8 결-3과 설계서 OQ-16.

---

## 1. 지금까지 뭐라고 적어 뒀나

이 이야기는 처음이 아닙니다. **6일 전에 「못 만들었다」고 적고 미뤄 둔 자리**입니다.

| 문서 | 적혀 있는 것 |
|---|---|
| 설계서 §5.8 | 폰 녹음 업로드 → **내 PC에서 Whisper로 전사** → AI 요약 → 회의록 초안 + 할 일은 인박스로 |
| 설계서 §14 **OQ-14** | 「브라우저만으로는 불가능하다」 — ① 로컬 프로그램 ② 전사 API ③ 붙여넣기. **7단계는 ③으로 만들었다** |
| 확인메모 **C-06** | 세 갈래를 표로 정리하고 *"어느 쪽이 좋으실지 알려주시면 그때 만들겠습니다"* 로 멈춤 |
| 회고 `2026-08-10_v02` 4-4 | *"녹음을 글로 바꾸는 기능을 못 만들었습니다"* — 붙여넣기로 우회 |
| 설계 모형 `data-flow` | 민감 회의 스위치, 사내 용어집 동봉(「타이백」→「타이벡」) |

**즉 미뤄 둔 이유는 「어려워서」가 아니라 「음성을 글로 바꾸는 자리를 어디에 둘지」를 안 정해서**입니다.
지금 그 결정을 합니다.

### ★ 그때는 없던 네 번째 갈래가 있습니다

C-06에 적은 세 갈래는 전부 **「녹음 파일을 나중에 처리한다」**는 전제였습니다.
노션이 하는 건 그게 아닙니다 — **회의가 진행되는 동안** 글자가 올라옵니다.

그리고 **요즘 브라우저에는 받아쓰기 기능이 내장돼 있습니다.** 설치할 것도, 켜 둘 컴퓨터도 없습니다.
C-06을 쓸 때 이걸 빠뜨렸습니다. 「음성 인식 = 무거운 계산 = 브라우저는 못 함」으로 단정했는데,
**브라우저가 직접 계산하는 게 아니라 브라우저 제조사 서버가 대신 해 주는 방식**이라 됩니다.

> ⚠️ 대신 **음성이 브라우저 제조사(크롬이면 구글) 서버로 나갑니다.** 이게 이 갈래의 값입니다.
> 뒤에서 다시 다룹니다.

## 2. 노션이 하는 일을 뜯어보면 세 층입니다

```
 ① 듣기          마이크로 소리를 받는다
      ↓
 ② 받아쓰기      소리를 글자로 바꾼다        ← 여기만 정하면 된다
      ↓
 ③ 정리          글자를 회의록으로 만든다     ← 이미 있다 (AI 규칙 4번)
```

- **①은 브라우저가 그냥 됩니다.** 마이크 권한만 받으면 됩니다.
- **③은 이미 만들어 둔 자리**입니다. AI가 하는 일 5가지 중 4번이 *"전사문 → 회의록 초안"*입니다.
  화면(회의록 붙여넣기)도, AI를 부르는 통로(Edge Function)도, 사내 용어집도 이미 있습니다.
- **②만 정하면 됩니다.** 아래가 그 선택지입니다.

## 3. 받아쓰기를 어디서 하나 — 네 갈래

| | 방식 | 음성이 어디까지 나가나 | 회의 중 실시간 | 정확도 | 비용 | 준비물 | 민감회의 |
|---|---|---|---|---|---|---|---|
| **④** | **브라우저 내장 받아쓰기** | 브라우저 제조사 서버 (크롬=구글) | ✅ **된다** | 중 | **0원** | 없음 | ❌ |
| ② | 녹음해서 AI 전사 서비스로 보냄 | OpenAI (이미 쓰는 곳) | △ 토막내 보내면 준실시간 | 상 | 분당 과금 | 없음 | ❌ |
| ① | 내 PC에서 도는 전사 프로그램 | **안 나감** | △ 만들기 나름 | 상 | 0원 | 설치 + 켜 두기 | ✅ |
| ③ | 전사문 붙여넣기 (지금) | 해당 없음 | ❌ | — | 0원 | 다른 도구 | ✅ |

> 금액을 적지 않는 것은 설계서 §8.2 규칙입니다. 공급자·단가가 자주 바뀝니다.
> ②를 고르면 그 시점 단가를 확인해 설계서에 적습니다.

### 추천 — ④ 브라우저 내장 받아쓰기

**이유 세 가지**

1. **오늘 붙일 수 있습니다.** 새로 설치할 것도, 새로 낼 돈도, 새로 만들 서버도 없습니다.
   ①은 파이썬 프로그램을 하나 더 만들어 계속 켜 둬야 하고, 그건 이 툴의 다른 부분이
   전부 「브라우저만 있으면 된다」로 되어 있는 것과 어긋납니다.
2. **실시간이 진짜로 됩니다.** 물어보신 그림 — 회의하는 동안 글자가 올라오는 것 — 이 방식이 원래 그것입니다.
   ②는 녹음을 토막내 계속 올려야 해서 「비슷하게 흉내」에 가깝습니다.
3. **틀려도 회의 중에 고칠 수 있습니다.** 나중에 파일을 돌리는 방식은 회의가 끝나야 결과를 봅니다.
   실시간은 잘못 들린 줄을 **그 자리에서** 고칠 수 있습니다. 이게 정확도 차이를 상당 부분 메웁니다.

**치르는 값 — 음성이 구글로 갑니다.** 이 툴의 대원칙은 *"밖으로 나가는 것은 사용자가 누른 것뿐"*입니다.
그래서 이렇게 막습니다.

| 지킬 것 | 어떻게 |
|---|---|
| 자동으로 켜지지 않는다 | 「듣기 시작」을 눌러야만 마이크가 열린다. 기본은 꺼짐 |
| 무엇이 나가는지 화면에 적는다 | 시작 버튼 옆에 *"음성이 브라우저 제조사 서버로 갑니다"* 를 상시 표시 |
| **민감 회의는 잠근다** | 「민감」을 켜면 시작 버튼이 눌리지 않는다 (설계서 §5.8) |
| 회의가 끝나면 마이크를 닫는다 | 「끝내기」·탭 닫기·30분 무음이면 자동 종료 |

### ②를 나중에 덧붙일 수 있습니다

④로 만들어 두면 ②는 **같은 화면에 버튼 하나 더**입니다.
받아쓰기가 너무 엉망이면 그때 「녹음 파일로 다시 전사」를 붙입니다. ①(로컬 프로그램)은
민감 회의를 실시간으로 받아써야 할 때만 필요하고, 그건 지금 필요가 확인되지 않았습니다.

## 4. 화면 기획

### 어디에 두나

모형(`nav-structure`)과 지금 화면 모두 **기록 › 회의록**입니다. 그 안에 두 갈래를 놓습니다.

```
 기록  [업무일지] [리포트] [회의록] [전화메모]
 └ 회의록 ─ [🎙 실시간]  [✍ 직접 쓰기]
              ↑ 새로 만드는 것   ↑ 지금 있는 붙여넣기 화면 (그대로 둠)
```

붙여넣기 화면을 **지우지 않습니다.** 받아쓰기가 안 되는 브라우저·마이크 없는 자리·
민감 회의에서 여전히 유일한 길입니다.

### 회의 중 — 왼쪽은 말, 오른쪽은 내가 적는 것

```
┌───────────────────────────────────────────────┬──────────────────────┐
│  ● 듣는 중   12:47        [⏸ 잠깐] [■ 끝내기] │  제목  자재 단가 협의 │
│  ⚠ 음성이 브라우저 제조사 서버로 갑니다        │  참석  대표, 구매담당  │
├───────────────────────────────────────────────┤  장소  본사 회의실     │
│  [00:12] 오늘 안건은 자재 단가 인상 통보입니다 │──────────────────────│
│  [01:40] ★ 이번 달 발주는 기존 단가로 갑니다   │  내 메모              │
│  [02:15] 대체 거래처를 알아보기로 …           │  ┌──────────────────┐│
│          ↑ 클릭하면 그 자리에서 고칠 수 있음   │  │ 견적 3곳 받을 것  ││
│                                               │  └──────────────────┘│
│  … 지금 들리는 말이 흐리게 이어서 보임         │  [★ 지금 중요] 버튼   │
└───────────────────────────────────────────────┴──────────────────────┘
```

| 장치 | 왜 필요한가 |
|---|---|
| **★ 지금 중요** | 회의 중엔 타자 칠 여유가 없습니다. 버튼 한 번이면 그 대목이 표시되고, AI가 초안에서 우선으로 다룹니다 |
| **줄 고치기** | 받아쓰기는 사람 이름·사내 용어에서 특히 틀립니다. 그 자리에서 고칩니다 |
| **내 메모** | 말로 안 나온 것(내 판단·다음에 할 일)을 적는 칸. 전사문과 섞이지 않게 따로 둡니다 |
| **잠깐 멈춤** | 회의 중 잡담·전화가 끼어들 때. 시간은 이어서 셉니다 |

### 회의 후 — AI 초안은 「제안」이지 회의록이 아닙니다

「끝내기」를 누르면 → **「회의록 초안 만들기」 버튼**이 나옵니다. 자동으로 안 부릅니다
(AI 호출은 사용자가 누를 때만 — 실수로 끝낸 회의에 요금이 나가지 않게).

AI가 돌려주는 것은 네 칸입니다.

| 칸 | 내용 | 어디로 가나 |
|---|---|---|
| 요약 | 무슨 이야기였나 | 회의록 「안건」 |
| 결정 | 정해진 것 | 회의록 「결정사항」 |
| 할 일 | 누가 무엇을 언제까지 | 줄마다 체크박스 → **체크한 것만 인박스로** |
| **확인 필요** | 잘못 들린 것 같은 대목 | 사람이 확인할 목록 |

「확인 필요」 칸은 이 툴에만 있는 것입니다. **받아쓰기가 틀릴 수 있다는 걸 AI가 먼저 말하게 합니다.**
용어집에 있는 말과 비슷하게 들린 대목(「타이백」 ↔ 「타이벡」)을 짚습니다.

**AI 초안과 사람이 고친 확정본을 둘 다 저장합니다** (CLAUDE.md — 그 차이가 "AI가 뭘 놓쳤나"를 알려주는 유일한 신호).

## 5. 데이터 — 표를 새로 만들지 않습니다

설계서 §7에는 `recordings`(녹음·전사문) 표가 예정돼 있었습니다. **④에서는 필요 없습니다** —
녹음 파일이 아예 안 생기기 때문입니다. 소리는 흘러가고 글자만 남습니다.

지금 회의록 표에 **칸 넷을 더합니다.**

| 더할 칸 | 무엇 | 왜 |
|---|---|---|
| 전사 방식 | `직접입력` / `실시간받아쓰기` | 나중에 정확도를 비교하려면 어느 쪽으로 만든 회의록인지 알아야 합니다 |
| AI 초안 | AI가 준 네 칸 원본 | 확정본과의 차이가 학습 신호입니다 |
| 회의 길이 | 몇 분짜리 회의였나 | 「1시간 회의가 회의록 한 줄」 같은 것이 리포트에서 보입니다 |
| 내 메모 | 회의 중 직접 적은 것 | 전사문과 섞으면 나중에 「내가 판단한 것」과 「누가 말한 것」이 구분 안 됩니다 |

### ⚠ 여기서 빠져 있던 것 하나

**회의록은 `disclosure_policy`(AI가 인용해도 되는지 정한 표)에 등록돼 있지 않습니다.**
`meetings`·`calls` 두 표가 통째로 빠져 있습니다.

회의록에는 **남이 한 말**이 그대로 들어갑니다. 지금까지는 사람이 요약해 적었으니 덜 위험했는데,
받아쓰기가 붙으면 **대표·거래처의 발언이 토씨까지 남습니다.** 이건 AI가 답변 근거로
꺼내면 안 되는 자료입니다. 이번에 **「인용 불가」로 등록**합니다.

## 6. 안 되는 것 — 미리 적어 둡니다

| 못 하는 것 | 왜 | 어떻게 다루나 |
|---|---|---|
| **누가 말했는지 구분** | 브라우저 받아쓰기는 목소리를 나누지 못합니다 | 참석자만 적고, 발언자 구분은 사람이 필요할 때 손으로 |
| **온라인 회의(줌·팀즈) 소리** | 마이크만 듣습니다. 스피커로 나오는 상대 목소리는 방 안 소리로만 잡힙니다 | 스피커를 켜 두면 대체로 잡힙니다. 정확도는 떨어집니다 |
| **탭을 닫으면** | 브라우저가 멈춥니다 | 받아쓴 것을 **브라우저에 계속 저장**해 두고, 다시 열면 이어서 복구 |
| **사투리·전문용어·겹쳐 말하기** | 받아쓰기의 한계 | 「확인 필요」 칸 + 줄 고치기 + 사내 용어집 |
| **파이어폭스** | 이 기능이 없습니다 | 못 쓰는 브라우저면 화면에서 미리 알리고 붙여넣기로 안내 |
| **긴 회의 비용** | 2시간 회의 전사문은 AI 입력이 큽니다 | 「중요」 표시한 대목을 앞에 두고, 너무 길면 나눠서 요약 |

## 7. 만드는 순서

| | 단계 | 무엇 | 이것만으로도 쓸 수 있나 |
|---|---|---|---|
| 1 | 계산 부분 | 들린 토막을 줄로 정리 · 시간 표시 · AI 답 나누기 (테스트 포함) | — |
| 2 | 듣는 장치 | 브라우저 받아쓰기 연결 · 끊기면 다시 붙기 · 권한 거부 처리 | — |
| 3 | 회의 중 화면 | 실시간 전사 · ★중요 · 줄 고치기 · 내 메모 · 브라우저에 임시 저장 | ✅ **받아쓰기 대체로 사용 가능** |
| 4 | AI 초안 | 회의록 모드 추가(전사문 + 용어집 → 네 칸) | ✅ 회의록 자동 작성 완성 |
| 5 | 이어 붙이기 | 할 일 → 인박스 · 회의록 저장(초안+확정본) · 공개정책 등록 | ✅ 전부 |
| 6 | 문서 | 설계서 §5.8·OQ-14 갱신 · 회고 · C-06 닫기 | — |

**3단계까지만 해도 쓸 수 있습니다** — 받아쓴 글을 지금 있는 회의록 화면에 넣으면 됩니다.
