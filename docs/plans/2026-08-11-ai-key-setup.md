# AI 열쇠 넣기 — 절차와 안전장치

> 2026-08-11 작성

---

## 30초 요약

```
1)  supabase/.env  파일을 엽니다 (이미 만들어 뒀습니다)
2)  OPENAI_API_KEY=  뒤에 열쇠를 붙여넣고 저장
3)  프로젝트 폴더에서 아래 한 줄

    npx supabase secrets set --env-file supabase/.env

4)  브라우저에서 업무 하나 열고 「AI 업무 지원」 눌러 보기
```

끝입니다. **화면 코드는 하나도 안 고칩니다.**

---

## ★ 가장 중요한 것 — 열쇠가 들어갈 자리는 하나입니다

```
브라우저  →  Edge Function  →  OpenAI
             ↑
             열쇠가 있는 유일한 자리
```

| | 넣는 곳 | 왜 |
|---|---|---|
| ⭕ | `supabase/.env` → Supabase 서버 | 서버에만 있고 브라우저는 못 봅니다 |
| ❌ | `frontend/.env.local` | **거기 값은 화면 소스에 실립니다** |

**`frontend/.env.local` 에 넣으면 안 되는 이유를 좀 더 —**

지금 당장은 안 샙니다. 화면 만드는 도구(Vite)가 `VITE_` 로 시작하는 값만 싣기 때문입니다.
문제는 그 **다음**입니다. *"어? AI가 안 되네"* 하다가 이름을 `VITE_OPENAI_API_KEY` 로
바꿔 보는 순간 **열쇠가 통째로 화면 소스에 실립니다.** 화면 소스는 주소창을 아는
누구나 열어 봅니다. 그러면 남이 우리 요금으로 AI를 씁니다.

> 그 한 번의 실수를 사람 주의력에 맡기지 않았습니다. 아래 「안전장치」 참고.

---

## 자세한 절차

### 1. 열쇠를 만듭니다

<https://platform.openai.com/api-keys> → **Create new secret key**

- 이름은 아무거나 (예: `work-management`)
- 만든 직후 **한 번만 보입니다.** 창을 닫으면 다시 못 봅니다
- `sk-` 로 시작하는 긴 문자열입니다

> 💡 결제 수단이 등록돼 있어야 실제로 호출됩니다. 처음에는
> **월 사용 한도(Usage limits)를 낮게 걸어 두시길** 권합니다. 예: $10.
> 뭔가 잘못 돌아도 거기서 멈춥니다.

### 2. 파일에 붙여넣습니다

`supabase/.env` 를 열면 이렇게 돼 있습니다.

```
OPENAI_API_KEY=
AI_PROVIDER=openai
AI_MODEL=gpt-4.1
AI_MODEL_LIGHT=gpt-4.1-mini
```

첫 줄 `=` 뒤에 붙여넣습니다. **따옴표를 붙이지 않습니다.**

```
OPENAI_API_KEY=sk-proj-여기에실제열쇠
```

> ⚠️ 이 파일은 git 이 무시하도록 해 뒀습니다. 저장소에 안 올라갑니다.
> (확인: `git check-ignore -v supabase/.env`)

### 3. 서버에 올립니다

프로젝트 폴더(`WorkManagement`)에서:

```bash
npx supabase secrets set --env-file supabase/.env
```

**왜 파일을 거치나** — 명령줄에 `OPENAI_API_KEY=sk-...` 를 직접 치면
그 줄이 **명령 기록에 그대로 남습니다.** PowerShell 은 기록을 파일에 저장하기 때문에
나중에 화면 공유나 백업으로 새어 나갈 수 있습니다. 파일을 거치면 안 남습니다.

### 4. 들어갔는지 확인합니다

```bash
npx supabase secrets list
```

**값은 안 보이고 이름과 지문(해시)만 나옵니다.** 그게 정상입니다.

### 5. 써 봅니다

브라우저에서 업무 하나 열고 → 「AI 업무 지원」 → 「물어보기」.

안 되면 아래 「안 될 때」로.

---

## 🛡 넣어 둔 안전장치 3개

사람이 매번 조심하는 대신 **도구가 막게** 해 뒀습니다.

### ① 화면 쪽에 열쇠를 넣으면 빌드가 멈춥니다

`frontend/vite.config.ts`

`VITE_` 로 시작하면서 이름에 `KEY`·`SECRET`·`TOKEN`·`PASSWORD` 가 들었거나,
값이 `sk-` 로 시작하면 **개발 서버도 빌드도 아예 안 뜹니다.** 이렇게 나옵니다:

```
🔴 화면에 실리면 안 되는 값이 frontend/.env.local 에 있습니다.
   · VITE_OPENAI_API_KEY — 이름부터 열쇠입니다. VITE_ 가 붙으면 화면 소스에 실립니다
```

> `VITE_SUPABASE_ANON_KEY` 는 통과합니다. **그건 원래 브라우저에 들어가는 값**이고,
> 남의 데이터를 막는 장치(RLS)가 따로 지키고 있습니다.

### ② 다 만들어진 파일을 훑어 봅니다

```bash
cd frontend && npm run check:keys
```

`npm run build` 뒤에 **자동으로 돕니다.** 환경변수가 아니라 **결과물 자체**를 읽어서
`sk-…` · `service_role` 같은 모양을 찾습니다. 코드에 문자열로 박아 넣은 것까지 잡힙니다.

두 검사가 보는 곳이 다릅니다 — ①은 설정을, ②는 결과물을.

### ③ git 이 파일 자체를 안 올립니다

`.gitignore`

```
supabase/.env
supabase/.env.*
!supabase/.env.example      ← 값 없는 틀만 커밋
supabase/functions/.env
```

## 🔴 하면 안 되는 것

| | |
|---|---|
| ❌ | 열쇠를 **채팅·메신저·이메일로 보내기** — 기록에 영구히 남습니다 |
| ❌ | `frontend/.env.local` 에 넣기 |
| ❌ | 코드 파일에 직접 적기 |
| ❌ | `service_role` 키를 어디든 쓰기 — 남의 데이터 막는 장치를 통째로 우회하는 마스터 키입니다 |
| ❌ | 스크린샷에 열쇠가 나온 채로 공유하기 |

**혹시 열쇠가 밖으로 나갔다면** — OpenAI 화면에서 그 열쇠를 **지우고(Revoke)** 새로 만듭니다.
"아마 괜찮겠지"로 넘어가지 않습니다. 지우는 데 10초 걸립니다.

## 모델 바꾸기

`supabase/.env` 에서 값만 고치고 3번 명령을 다시 돌립니다. **코드는 안 고칩니다.**

| 변수 | 쓰는 곳 |
|---|---|
| `AI_MODEL` | 질문에 답하기 — 판단이 섞임 |
| `AI_MODEL_LIGHT` | 체크리스트 추리기 — 뽑아내기라 가벼움 |

> 지금 값은 **임시로 정한 것**입니다 (설계서 §14 OQ-12 미확정).
> 써 보시고 답이 부실하면 상위 모델로, 너무 비싸면 하위 모델로 바꾸면 됩니다.

## 공급자 바꾸기 (나중에)

`AI_PROVIDER` 를 바꾸고 `supabase/functions/_shared/provider/` 에 어댑터를 하나 더 넣습니다.
**화면과 저장 공간은 안 고칩니다.** 원래 Claude 를 쓰려다 호출이 반복 실패해 OpenAI 로
바꾼 적이 있어서(설계서 §14 OQ-11) 그 대비로 한 겹 둔 것입니다.

## 안 될 때

| 화면에 뜨는 말 | 뜻 | 할 것 |
|---|---|---|
| *AI 열쇠가 아직 등록되지 않았습니다* | 서버에 열쇠가 없음 | 3번 명령을 돌렸는지 확인 |
| `AI 호출 실패 (401)` | 열쇠가 틀렸거나 지워짐 | 열쇠를 다시 만들어 3번부터 |
| `AI 호출 실패 (429)` | 한도 초과 또는 너무 잦음 | OpenAI 결제·한도 확인 |
| `AI 호출 실패 (404)` ... model | 그 모델을 못 씀 | `AI_MODEL` 을 다른 값으로 |
| *로그인 정보를 확인하지 못했습니다* | 로그인이 풀림 | 새로고침 후 다시 로그인 |

**어느 경우든 업무·체크리스트·파일은 멀쩡합니다.** AI 칸만 안 될 뿐입니다.

서버 쪽 기록을 보려면:

```bash
npx supabase functions logs ai-assist
```

> 기록에 열쇠 값은 안 찍힙니다. 오류 본문을 400자만 잘라 올리도록 해 뒀습니다.
