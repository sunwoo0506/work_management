# 1부. 배포 — Cloudflare Pages

## 왜 Vercel이 아니라 Cloudflare인가

둘 다 이 앱을 잘 올립니다. 화면만 있고 서버가 없는 구조(정적 사이트)라서 기술적으로는 차이가 거의 없습니다. **갈린 지점은 딱 하나입니다.**

| | Vercel 무료(Hobby) | **Cloudflare Pages 무료** |
|---|---|---|
| **회사 업무에 써도 되나** | ❌ **안 됩니다.** 무료 요금제는 개인·비상업용 전용입니다 | ✅ **됩니다.** 상업적 이용 제한이 없습니다 |
| 회사에 쓰려면 | 유료 전환 필요 (인당 월 20달러) | 그대로 무료 |
| 로그인 벽을 앞에 세울 수 있나 | 유료부터 | ✅ 무료 (Cloudflare Access, 50명까지) |
| 속도·안정성 | 충분 | 충분 |

**이건 회사 업무 도구입니다.** Vercel 무료로 올리면 약관 위반이고, 지키려면 돈이 듭니다. Cloudflare는 같은 걸 무료로 허용합니다. 그래서 Cloudflare로 정했습니다.

> 덤 — Cloudflare는 **사이트 앞에 로그인 벽을 하나 더 세우는 기능(Access)이 무료**입니다. 지금도 이 앱에 로그인이 있지만, "주소를 아는 사람은 로그인 화면까지는 볼 수 있다"가 걸리면 그 앞을 통째로 막을 수 있습니다.

```

```

## ★ 서버 함수는 **웹 편집기 말고 CLI 로** 올립니다 *(2026-09-08 추가)*

Supabase 대시보드에도 함수를 고치는 편집기가 있습니다. **거기서 배포하면 깨집니다.**

```
Failed to deploy edge function: Failed to bundle the function
(reason: Module not found ".../_shared/usage.ts")
```

**왜 그런가** — 이 저장소의 함수들은 여러 함수가 같이 쓰는 코드를
`supabase/functions/_shared/` 에 모아 뒀습니다. 그런데 그 폴더는
**함수 폴더 바깥**에 있습니다.

```
supabase/functions/
├── _shared/          ← 여기는 웹 편집기에 안 보입니다
│   ├── usage.ts
│   └── provider/
├── ai-assist/        ← 웹 편집기는 이 안만 압니다
└── transcribe/
```

웹 편집기는 **그 함수 폴더 안만** 압니다. CLI 는 `import` 를 따라가며
필요한 파일을 **스스로 찾아 올립니다.**

```
Uploading asset (ai-assist): supabase/functions/ai-assist/index.ts
Uploading asset (ai-assist): supabase/functions/_shared/provider/index.ts
Uploading asset (ai-assist): supabase/functions/_shared/usage.ts   ← CLI 만 이걸 올립니다
```

**함수 12개가 전부 `_shared/` 를 씁니다.** 그러니 예외 없이 CLI 로 올립니다.

```
npx supabase functions deploy ai-assist
npx supabase functions deploy transcribe
```

> ⚠️ 웹 편집기에서 급하게 한 줄 고치는 것도 하지 않는 편이 낫습니다.
> 저장소와 서버가 달라지고, **다음 CLI 배포 때 조용히 덮어써집니다.**
> 그러면 「분명히 고쳤는데 왜 안 되지」가 됩니다.

> `WARNING: Docker is not running` 은 무시해도 됩니다. 로컬 스택용 경고이고,
> 배포는 클라우드로 바로 갑니다.

### ★ 가장 중요한 것 — 열쇠가 들어갈 자리는 하나입니다

```
브라우저  →  Edge Function  →  OpenAI
             ↑
             열쇠가 있는 유일한 자리
```

| | 넣는 곳 | 왜 |
|---|---|---|
| ⭕ | `supabase/.env` → Supabase 서버 | 서버에만 있고 브라우저는 못 봅니다 |
| ❌ | `frontend/.env.local` | **거기 값은 화면 소스에 실립니다** |

**`frontend/.env.local` 에 넣으면 안 되는 이유를 좀 더 —**

지금 당장은 안 샙니다. 화면 만드는 도구(Vite)가 `VITE_` 로 시작하는 값만 싣기 때문입니다.
문제는 그 **다음**입니다. *"어? AI가 안 되네"* 하다가 이름을 `VITE_OPENAI_API_KEY` 로
바꿔 보는 순간 **열쇠가 통째로 화면 소스에 실립니다.** 화면 소스는 주소창을 아는
누구나 열어 봅니다. 그러면 남이 우리 요금으로 AI를 씁니다.

> 그 한 번의 실수를 사람 주의력에 맡기지 않았습니다. 아래 「안전장치」 참고.

---

### 자세한 절차

#### 1. 열쇠를 만듭니다

<https://platform.openai.com/api-keys> → **Create new secret key**

- 이름은 아무거나 (예: `work-management`)
- 만든 직후 **한 번만 보입니다.** 창을 닫으면 다시 못 봅니다
- `sk-` 로 시작하는 긴 문자열입니다

> 💡 결제 수단이 등록돼 있어야 실제로 호출됩니다. 처음에는
> **월 사용 한도(Usage limits)를 낮게 걸어 두시길** 권합니다. 예: $10.
> 뭔가 잘못 돌아도 거기서 멈춥니다.

#### 2. 파일에 붙여넣습니다

`supabase/.env` 를 열면 이렇게 돼 있습니다.

```
OPENAI_API_KEY=
AI_PROVIDER=openai
AI_MODEL=gpt-4.1
AI_MODEL_LIGHT=gpt-4.1-mini
```

첫 줄 `=` 뒤에 붙여넣습니다. **따옴표를 붙이지 않습니다.**

```
OPENAI_API_KEY=sk-proj-여기에실제열쇠
```

> ⚠️ 이 파일은 git 이 무시하도록 해 뒀습니다. 저장소에 안 올라갑니다.
> (확인: `git check-ignore -v supabase/.env`)

#### 3. 서버에 올립니다

프로젝트 폴더(`WorkManagement`)에서:

```bash
npx supabase secrets set --env-file supabase/.env
```

**왜 파일을 거치나** — 명령줄에 `OPENAI_API_KEY=sk-...` 를 직접 치면
그 줄이 **명령 기록에 그대로 남습니다.** PowerShell 은 기록을 파일에 저장하기 때문에
나중에 화면 공유나 백업으로 새어 나갈 수 있습니다. 파일을 거치면 안 남습니다.

#### 4. 들어갔는지 확인합니다

```bash
npx supabase secrets list
```

**값은 안 보이고 이름과 지문(해시)만 나옵니다.** 그게 정상입니다.

#### 5. 써 봅니다

브라우저에서 업무 하나 열고 → 「AI 업무 지원」 → 「물어보기」.

안 되면 아래 「안 될 때」로.

두 검사가 보는 곳이 다릅니다 — ①은 설정을, ②는 결과물을.

| ❌ | `service_role` 키를 어디든 쓰기 — 남의 데이터 막는 장치를 통째로 우회하는 마스터 키입니다 |
| ❌ | 스크린샷에 열쇠가 나온 채로 공유하기 |

**혹시 열쇠가 밖으로 나갔다면** — OpenAI 화면에서 그 열쇠를 **지우고(Revoke)** 새로 만듭니다.
"아마 괜찮겠지"로 넘어가지 않습니다. 지우는 데 10초 걸립니다.

### 모델 바꾸기

`supabase/.env` 에서 값만 고치고 3번 명령을 다시 돌립니다. **코드는 안 고칩니다.**

| 변수 | 쓰는 곳 |
|---|---|
| `AI_MODEL` | 질문에 답하기 — 판단이 섞임 |
| `AI_MODEL_LIGHT` | 체크리스트 추리기 — 뽑아내기라 가벼움 |

> 써 보시고 답이 부실하면 상위 모델로, 너무 비싸면 하위 모델로 바꾸면 됩니다.

### 로그인 — 문이 둘입니다 (2026-09-05부터)

| | 메일 링크 | **비밀번호** |
|---|---|---|
| 메일이 나가나 | ○ | ✕ |
| 막힐 수 있나 | **○ — 시간당 두 통까지만** | ✕ |
| 처음 오는 사람 | **이것만 됩니다** | 아직 정한 게 없어 못 씁니다 |

**비밀번호 정하는 법** — 로그인한 뒤 **기준 › 설정 › 로그인 비밀번호**. 10자 이상.

> ⚠️ **처음 한 번은 반드시 메일 링크로 들어와야 합니다.**
> 비밀번호를 정하려면 로그인해 있어야 하기 때문입니다.

#### `email rate limit exceeded` 가 뜰 때

**Supabase 가 무료로 얹어 주는 메일 발송기는 시간당 두 통이 끝입니다.** 늘리는 설정이 없습니다.

1. **메일함(스팸함 포함)을 먼저 봅니다.** 이미 온 링크가 있을 수 있고 **1시간 유효**합니다
2. 없으면 **1시간 뒤에 한 번만** 누릅니다 — ⚠️ 여러 번 누르면 한도만 더 씁니다
3. 들어오신 뒤 **비밀번호를 정해 두시면 다시는 안 걸립니다**

메일을 자주 쓰셔야 하면 **전용 발송기(SMTP)를 등록**하는 길이 있습니다 —
대시보드 › Authentication › SMTP Settings. Resend·SendGrid 같은 곳이 무료 구간을 줍니다.
등록하면 시간당 두 통 제한이 사라지고 한도를 직접 올릴 수 있습니다.
**지금은 비밀번호가 있어 급하지 않아 안 했습니다.**

#### `Failed to fetch` 가 뜰 때

**서버가 잠든 것입니다.** 무료 요금제는 **7일간 아무도 안 쓰면 프로젝트를 잽니다.**
주소가 인터넷에서 통째로 사라져 로그인 화면조차 못 붙습니다.

1. https://supabase.com/dashboard → 프로젝트 → **Restore / Resume**
2. **2~5분** 기다립니다. 데이터는 안 지워집니다
3. 살아났는지 확인 — `curl -s -o /dev/null -w "%{http_code}" https://mpcphuyvffsccsmrocwu.supabase.co/auth/v1/health`
   (`401` 이 나오면 **살아 있는 것**입니다. 서버가 답하고 있다는 뜻입니다)

> ⚠️ **비밀번호가 있어도 이건 못 피합니다.** 서버가 꺼진 것이라 어느 문으로도 못 들어갑니다.
> 이 문제를 어떻게 할지는 아직 안 정했습니다 — 할 일 문서 **T-17**.

### 받아쓰기 모델 — 화면에서 고릅니다 (2026-09-05부터)

**회의록 받아쓰기 모델은 이제 코드에 박혀 있지 않습니다.** 화면에서 눌러서 고릅니다.

| 고르는 자리 | 언제 |
|---|---|
| 기록 › 회의록 › 🎙 실시간 › **🎧 녹음** | 「받아쓰기 시작」을 누르기 **전** |
| 기록 › 회의록 › **녹음파일 올리기** | 「변환 시작」을 누르기 **전** |
| 회의록 상세 › **변환하지 못한 음성** | 「다시 변환」을 누르기 전 — 같은 소리를 다른 모델로 돌려 견주는 자리 |

고른 값은 **그 브라우저에 기억됩니다.** 폰과 컴퓨터에서 다른 모델을 쓸 수 있습니다.

> ⚡ 브라우저 받아쓰기 쪽에는 이 칸이 안 나옵니다. 그건 서버를 안 거치고
> 브라우저 제조사가 직접 받아쓰기 때문에 고를 것이 없습니다.

#### 고를 수 있는 것

| 모델 | 어디 것 | 1분당 | 「말이 맞나」 숫자 | |
|---|---|---|---|---|
| **제미나이 받아쓰기** (`gemini-3.5-transcribe`) | 구글 | 약 $0.0035 | ❌ 안 준다 | **← 기본값** |
| **GPT 받아쓰기** (`gpt-transcribe`) | OpenAI | 약 $0.0045 | ❌ 안 준다 | |
| **Whisper** (`whisper-1`) | OpenAI | 약 $0.006 | ✅ **준다** | ← 되돌릴 자리 |

#### ⚠️ 「말이 맞나」 숫자가 무엇이고, 왜 중요한가

받아쓰기 모델은 유튜브 자막을 대량으로 보고 배웠습니다. 그래서 **소리가 흐릿한 구간**을 받으면 빈 답을 내는 대신 자막에서 흔한 문장을 지어냅니다. 실제로 「시청해주셔서 감사합니다」가 회의록에 들어왔습니다(2026-08-19).

**Whisper는 구간마다 「이게 정말 말이었나」를 숫자로 같이 줍니다.** 재 봤더니 무음 구간은 0.802, 사람 말은 0.008 — **100배** 차이였습니다. 그 숫자로 지어낸 말을 걸러 왔습니다.

**다른 두 모델은 그 숫자를 주지 않습니다.** 걸러 내는 그물이 「알려진 헛소리 낱말 목록」 한 겹만 남습니다. 처음 보는 헛소리는 못 걸러집니다.

> **2026-09-05 에 셋을 같은 소리로 재 보고 이 판단을 뒤집었습니다.**
> 무음을 넣었을 때 **지어낸 쪽은 오히려 Whisper 였고**(우리가 넘긴 사내 용어를
> 되뇌었습니다), 나머지 둘은 빈 글을 냈습니다. 정확도도 제미나이가 이겼습니다 —
> **「타이벡」을 맞힌 것은 그것뿐**이었습니다.
>
> **그래서 기본값을 제미나이로 바꿨습니다.** Whisper 는 목록에 남아 있습니다 —
> 새 모델이 이상하면 **화면에서 한 번 누르면** 그전으로 돌아갑니다.
>
> ⚠️ 한 번 잰 것뿐입니다. 폰 녹음(webm)과 진짜 회의 소리는 아직 안 쟀습니다.

#### ⚠️ 제미나이는 분당 한도가 있습니다

**1분 동안 보낼 수 있는 양이 정해져 있습니다** (입력 1만 토큰). 넘으면 거절하고
「몇 초 뒤에 오라」고 알려 줍니다. **잔액 문제가 아닙니다.**

| | 괜찮나 |
|---|---|
| 🎙 실시간 회의록 (15초씩) | ✅ 넉넉합니다 |
| 🎧 녹음파일 올리기 (5분씩) | ⚠️ **한 줄로 보냅니다** — 셋씩 동시에 보내면 첫 묶음부터 거절당합니다 |

그래서 녹음파일 변환은 **제미나이일 때만 느립니다.** OpenAI 모델은 그대로
셋씩 보냅니다 — 급하게 긴 녹음을 변환하셔야 하면 그때만 `gpt-transcribe` 로
바꾸시는 것도 방법입니다.

> 2026-09-05 에 이 한도에 실제로 걸렸습니다. 그때 툴이 **「OpenAI 크레딧 잔액이
> 없습니다」**라고 잘못 안내했습니다 — 오류 본문에 `quota` 라는 낱말이 들어 있다는
> 이유로 잔액 문제로 본 것입니다. 지금은 갈라서 안내하고, **말해 준 시간만큼
> 기다렸다 다시 시도**합니다.

#### 제미나이를 쓰려면 — 열쇠를 하나 더 넣습니다

1. https://aistudio.google.com/apikey 에서 열쇠를 만듭니다
2. `supabase/.env` 의 `GEMINI_API_KEY=` 뒤에 붙여넣습니다 (따옴표 없이)
3. 위 **3번 명령**을 다시 돌립니다 — `npx supabase secrets set --env-file supabase/.env`

**안 넣어도 OpenAI 모델 두 개는 그대로 돕니다.** 제미나이를 골랐는데 열쇠가 없으면
「제미나이 열쇠(GEMINI_API_KEY)가 설정되지 않았습니다」라고 화면에 뜹니다.

#### 고를 수 있는 목록을 잠그고 싶을 때

```
AI_TRANSCRIBE_MODELS=whisper-1,gemini-3.5-transcribe
```

비워 두면 잠그지 않습니다. **일부러 안 잠갔습니다** — 모델은 몇 달마다 새로 나오는데,
목록을 코드나 설정에 박아 두면 새 모델을 한 번 써 보려고 배포를 다시 해야 합니다.

### 안 될 때

| 화면에 뜨는 말 | 뜻 | 할 것 |

| *AI 열쇠가 아직 등록되지 않았습니다* | 서버에 열쇠가 없음 | 3번 명령을 돌렸는지 확인 |
| `AI 호출 실패 (401)` | 열쇠가 틀렸거나 지워짐 | 열쇠를 다시 만들어 3번부터 |

| *로그인 정보를 확인하지 못했습니다* | 로그인이 풀림 | 새로고침 후 다시 로그인 |
| *제미나이 열쇠(GEMINI_API_KEY)가 설정되지 않았습니다* | 구글 열쇠가 없음 | 위 「제미나이를 쓰려면」 3단계 · 또는 모델을 Whisper 로 되돌리기 |

**어느 경우든 업무·체크리스트·파일은 멀쩡합니다.** AI 칸만 안 될 뿐입니다.
