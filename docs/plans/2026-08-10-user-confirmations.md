### C-10. AI 열쇠를 넣어 주세요 ⏳ 2026-08-11 추가

**AI 업무 지원을 만들어서 올려 뒀습니다.** 화면·서버·규칙이 전부 붙어 있고,
**열쇠(API 키) 한 줄만 넣으면 그 자리에서 동작합니다.** 지금 누르면
*"AI 열쇠가 아직 등록되지 않았습니다"* 라고 뜹니다.

**하시는 방법** — 둘 중 편한 쪽으로.

```
① 웹에서
   supabase.com → WorkManagement 프로젝트 → Edge Functions → Secrets
   OPENAI_API_KEY = sk-...  를 추가

② 명령으로 (터미널에 그대로 붙여넣기)
   npx supabase secrets set OPENAI_API_KEY=sk-...
```

> ⚠️ **열쇠를 저에게 채팅으로 보내지 마세요.** 대화 기록에 남습니다.
> 위 방법은 열쇠가 서버에만 들어가고 브라우저에는 안 들어갑니다.
> (빌드 결과물에 열쇠 문자열이 없는지 검사해서 확인했습니다.)

**모델(OQ-12)은 일단 이렇게 정해 뒀습니다** — 언제든 바꿉니다.

| 환경변수 | 지금 값 | 쓰는 곳 |
|---|---|---|
| `AI_MODEL` | `gpt-4.1` | 질문에 답하기 — 판단이 섞임 |
| `AI_MODEL_LIGHT` | `gpt-4.1-mini` | 체크리스트 추리기 — 뽑아내기라 가벼움 |

바꾸시려면 위와 같은 방법으로 `AI_MODEL=<모델명>` 을 넣으면 됩니다.
**코드는 안 고칩니다.** 모델명이 코드에 박혀 있지 않습니다.

### C-12. 실시간 회의록 ✅ 2026-08-16 추가

**어디에 있나** — 기록 › 회의록 › **「🎙 실시간」**

**처음 한 번만 할 일** — 「듣기 시작」을 누르면 브라우저가 *"마이크를 사용하시겠습니까"* 를
물어봅니다. **허용**을 누르시면 됩니다. 다음부터는 안 묻습니다.

**어떻게 쓰나**

```
제목 적기 → 듣기 시작 → (회의) → 끝내기 → 회의록 초안 만들기 → 고쳐서 저장
```

**받아쓰는 방법이 두 가지입니다** (시작 전에 고르실 수 있습니다)

| | ⚡ 브라우저 | 🎧 녹음 |
|---|---|---|
| 글자가 보이는 때 | 말하는 즉시 | **45초쯤 뒤에 한 덩어리씩** |
| **폰 · 갤럭시탭** | 잘 안 됩니다 | **✅ 됩니다** |
| 사내 용어 미리 알려주기 | ✕ | **○ 더 정확합니다** |
| 요금 | 0원 | 소리 길이만큼 붙습니다 |

**폰·탭에서 여시면 자동으로 「🎧 녹음」이 골라집니다.** 노트북에서는 「⚡ 브라우저」입니다.
바꾸고 싶으시면 시작 전에 누르시면 됩니다.

> 폰에서 글자가 안 올라왔던 것은 「⚡ 브라우저」 쪽이 폰에서 잘 안 되기 때문입니다.
> 이제 폰에서는 처음부터 「🎧 녹음」으로 열립니다.

**듣고 있는지 어떻게 아나** — 「🎧 녹음」이면 **소리 막대**가 움직입니다. 말할 때 막대가
차오르면 마이크가 잡고 있는 것입니다. 「⚡ 브라우저」면 *"말소리 감지됨"* 같은 상태가 뜹니다.

- 회의 중 중요한 말이 나오면 **「★ 지금 중요」** 를 누르세요. AI가 그 대목을 우선으로 다룹니다
- 잘못 들린 줄은 **그 줄을 눌러 그 자리에서 고칠 수 있습니다**
- 회의록의 「할 일」은 **체크한 것만 인박스로** 갑니다
- 탭이 닫혀도 **저장 안 한 회의는 복구**됩니다

**⚠️ 꼭 아셔야 할 것 — 음성이 밖으로 나갑니다**

받아쓰기는 브라우저 제조사(크롬이면 구글) 서버가 해 줍니다.

말씀하신 대로 **민감 회의(회생·인사)도 막지 않았습니다.** 일반 회의와 똑같이 쓰시면 됩니다.
다만 **「민감 회의」 체크는 켜 주세요.** 막는 스위치가 아니라 **표시**입니다 —
나중에 보안을 다시 볼 때 *"그동안 쌓인 민감 회의가 어느 것이냐"* 를 그 표시로 골라냅니다.
표시가 없으면 그때 회의록을 전부 뒤져야 합니다.

> 지금 실제로 일어나는 일: 회생·인사 회의도 **음성이 밖으로 나가고, 전사문이 클라우드에 저장되고,
> 초안을 만들 때 AI에게 넘어갑니다.** 알고 쓰시는 것과 모르고 쓰시는 것은 다르니 적어 둡니다.
> 되돌리는 방법은 설계서 OQ-16에 세 가지로 적어 두었습니다.

**알려 주셨으면 하는 것 두 가지**

| | 물음 | 왜 |
|---|---|---|
| 1 | **받아쓰기가 쓸 만합니까?** (설계서 OQ-15) | 여러 사람이 겹쳐 말하는 회의에서 얼마나 알아듣는지는 실제로 써 봐야 압니다. 못 쓸 수준이면 다른 방법(녹음 파일 → 정밀 전사)을 덧붙입니다 |
| 2 | 크롬·엣지를 쓰십니까? | 파이어폭스에서는 이 기능이 없습니다. 화면에서 미리 알려 드리긴 합니다 |
| 3 | **폰·갤럭시탭에서 화면이 잘 보입니까?** | 폰·탭에서 쓰신다고 하셔서 화면을 손봤습니다(메뉴가 위로 올라가고, 칸이 세로로 쌓입니다). 실제 기기에서 눌러 보셔야 압니다 |

> 💡 **기준 › 설정 › 사내 용어집**을 채워 두시면 받아쓰기 오류가 줄어듭니다.
> 타이벡·마더롤·원지정비처럼 밖에서 안 쓰는 말을 넣어 두시면, 「타이백」으로 들려도
> 회의록에는 **「타이벡」** 으로 적힙니다. 지금은 비어 있습니다.

**요금** — 2026-08-16에 단가를 직접 확인했습니다 (1달러 = 1,417원 기준).

| 무엇 | 1시간 회의 |
|---|---|
| ⚡ 브라우저로 받아쓰기 | **0원** |
| 🎧 녹음으로 받아쓰기 | **약 510원** (분당 $0.006) |
| 회의록 초안 만들기 (AI) | **약 100원** |

**한 달에 얼마인가** — 주 2회, 1시간짜리 회의를 폰으로 하신다고 보면 **월 5,000원 안쪽**입니다.
매일 2시간씩 해도 월 2만원대입니다.

> 💡 **절반으로 줄이는 방법이 있습니다.** 받아쓰기 모델을 `gpt-4o-mini-transcribe` 로 바꾸면
> 분당 $0.003 — **1시간에 255원**이 됩니다. 정확도를 먼저 비교해 보고 정하시면 됩니다.
> 바꾸는 것은 명령 한 줄입니다: `npx supabase secrets set AI_MODEL_TRANSCRIBE=gpt-4o-mini-transcribe`

화면에 뜬 말이 어느 쪽인지 보세요.

| **AI 열쇠가 거부됐습니다** | 열쇠가 틀렸거나 지워졌습니다 | C-10을 다시 해 주세요 |

> 💡 **어느 쪽인지 빠르게 가리는 법** — 업무 하나를 열고 **클로니(AI 비서)에게 아무거나 물어보세요.**

**저장 용량은 걱정 안 하셔도 됩니다** (2026-08-16 실제로 재 봤습니다)

### C-11. 못 읽는 파일 형식이 있습니다 🟡 2026-08-11 추가

**파일을 올리면 브라우저가 그 자리에서 글을 뽑아 둡니다.** 그래야 AI가 읽습니다.
그런데 **전부 읽지는 못합니다.**

| 읽습니다 | 못 읽습니다 |
|---|---|
| PDF (쪽 번호까지 붙여서) | **한글(.hwp / .hwpx)** |
| 워드 `.docx` | 엑셀 `.xlsx` |
| `.txt` · `.csv` · `.md` · `.json` | 스캔한 그림 PDF · 사진 속 글자 |

**못 읽는 파일도 보관은 됩니다.** 목록에서 왜 못 읽었는지 그 자리에 뜨고,
AI에게 물으면 *"이 파일은 못 읽었습니다"* 라고 답합니다 — 아는 척하지 않습니다.

**제 판단** — 한글 파일이 실무에서 많으실 텐데, 지금은 *"PDF로 저장해 올려 주세요"* 로 안내합니다.
한글 파일을 직접 읽으려면 별도 프로그램이 필요해서 브라우저만으로는 안 됩니다.
**자주 걸리시면 알려 주세요.** 그러면 서버 쪽에서 변환하는 길을 알아보겠습니다(파일이 한 번 더 밖으로 나가는 대가가 있습니다).

### C-09. 아직 안 써보신 화면 — 절차와 일지 🟡

업무·지시사항은 확인하셨습니다. **아직 한 번도 안 돌려본 것이 둘 남았습니다.**

| 탭 | 해볼 것 |
|---|---|
| **절차** | 「＋ 새 절차」 → 단계 2~3개 → **상태를 「확정」으로** → 「이번 회차 시작」 |
| | 시작하면 **업무가 자동으로 생깁니다** |
| | 단계를 체크하고 소요시간을 적은 뒤 「회차 완료」 |
| | 필수 단계를 일부러 건너뛰고 완료 → **예외 확인함**에 잡혀야 합니다 |
| **기록** | 「오늘 일지 열기」 → 이슈·내일 할 일 적고 **일부만 체크** → 「일지 확정」 |
| | 다음날 「오늘」 탭 **어제 이야기**에 뜨는지 |

**미리 알려드릴 것** — 절차는 **상태를 「확정」으로 바꿔야** 「절차 대기」에 뜹니다.
「초안」이면 안 뜹니다. 헷갈리시면 알려주세요, 기본값을 바꾸겠습니다.

> 💡 D-11(일일 현금표)처럼 **매일 하는 일**을 첫 절차로 만들어 보시면 감이 옵니다.

### D-06. 전체 목록을 「접었다 폈다」로 만들었습니다 (2026-08-11)

**질문하신 것** — *"섹션만 나눌지 토글까지 적용할지 니가 판단해봐"*

**제가 한 것** — **토글까지 적용했습니다.** 다만 전부 접지는 않았습니다.

**왜** — 나누기만 하면 줄 수가 그대로입니다. 46줄이 11묶음으로 나뉜 46줄이 될 뿐이라
"복잡해 보인다"가 안 풀립니다. 그렇다고 전부 접으면 오늘 볼 것을 보려고 매번 눌러야 합니다.

**그래서 이렇게 했습니다**

```
지연이나 오늘 마감이 있는 영역  →  펴 둡니다   (그냥 보입니다)
나머지 영역                     →  접어 둡니다  (제목 줄만)
```

묶음 **순서도 급한 것이 위**입니다. 가나다순이면 오늘 터질 일이 맨 아래로 갑니다.
접혀 있어도 제목 줄에 `지연 3` `오늘 1` 이 붙어서 안 열어도 압니다.
맨 위에 「전부 펴기 / 전부 접기」가 있습니다.

**대가** — 어느 영역이 펴져 있는지가 **매번 화면을 새로 열 때마다 초기화**됩니다.
직접 접은 것을 기억하려면 저장 공간이 하나 더 필요한데, 지금 그럴 값어치는 없다고 봤습니다.
불편하시면 알려 주세요.

### D-07. 오늘 마감에 새 색을 안 썼습니다 (2026-08-11)

**하신 말씀** — *"오늘 마감인 것들은 하이라이트를 주면 좋을 것 같아"*

**제가 한 것** — 하이라이트는 넣되 **색을 새로 만들지 않았습니다.**
줄 배경이 밝아지고, 왼쪽에 검은 기둥이 서고, 제목이 굵어지고, 「오늘 마감」 배지에 테두리가 생깁니다.

**왜** — 작업 규칙(`CLAUDE.md`)에 색이 딱 둘로 정해져 있습니다.
파란색 = 누를 수 있는 것, 빨간색 = 기한 초과. **오늘 마감은 둘 다 아닙니다.**
빨간색을 쓰면 진짜 지연된 건이 안 보이게 되고, 파란색을 쓰면 누를 수 있는 것처럼 보입니다.

**보시고 약하다 싶으면** 알려 주세요. C-07(회생 건)과 같은 고민이라 같이 정하면 좋겠습니다.

### D-08. 진행률 막대를 잠갔습니다 (2026-08-11)

**하신 말씀** — *"진행률은 체크박스 처리 건으로 자동 계산되게 해줘"*

**제가 한 것** — 자동 계산에 더해, **체크리스트가 있으면 진행률 막대를 손으로 못 끌게** 했습니다.

**왜** — 둘 다 열어 두면 어느 쪽이 맞는지 알 수 없습니다.
체크리스트로 60%인데 막대를 90%로 끌어 두면, 3개월 뒤에 그 90%가 무슨 뜻인지 아무도 모릅니다.

**체크리스트가 하나도 없는 업무는** 예전처럼 손으로 끕니다.
모든 업무에 체크리스트를 만들라고 강요하지 않기 위해서입니다.

### D-01. 시드를 마이그레이션이 아니라 앱에서 만든다

**문제** — 업체와 지시사항에는 `user_id`가 필요한데, 마이그레이션 SQL에 특정 사용자 UUID를 박으면 **다른 환경에서 안 돌아갑니다.**

**제가 한 것** — 로그인 후 앱이 최초 진입 시 **업체가 하나도 없으면 자동으로 만들도록** 했습니다. 지시사항 13건도 그때 같이 들어갑니다.

**대가** — 시드 내용이 SQL이 아니라 TypeScript 파일(`frontend/src/features/seed/`)에 있습니다. 나중에 바꾸려면 그 파일을 고칩니다.

### D-02. `activity` 기록을 앱에서 남긴다 (DB 트리거 아님)

**선택지** — ① 앱 코드에서 남긴다 ② DB 트리거로 자동으로 남긴다

**제가 한 것** — ①. 업무 상태를 바꿀 때 등 **의미 있는 순간에만** 남깁니다.

**왜** — 트리거는 모든 변경을 남겨서 노이즈가 많고, "무엇이 의미 있는 변경인가"는 업무 규칙이라 DB보다 앱이 알기 좋습니다. 대신 앱에서 빠뜨리면 기록이 안 남습니다.

### D-03. 업무 순서는 사람이 직접 바꾸지 않는다

**제가 한 것** — `sort_order` 컬럼은 만들어 뒀지만 **화면에서 쓰지 않습니다.** 정렬은 `domain/sort.ts`가 정한 순서(일정 상태 → 중요도 → 기한)를 따릅니다.

**왜** — 설계서 §6.9의 정렬 규칙이 이미 있고, 사람이 손으로 옮긴 순서와 자동 정렬이 부딪히면 어느 쪽이 맞는지 알 수 없습니다. 필요해지면 나중에 켭니다.

### D-04. 「이슈로 공유」 버튼은 자리만 만들어 뒀다

**제가 한 것** — 업무 상세에 버튼을 두되, 누르면 *"6단계에서 연결됩니다"* 안내만 뜹니다.

**왜** — 연동 계약서가 초안 상태입니다. 지금 만들면 계약이 바뀔 때 다시 만들어야 합니다.

### D-05. 칸반에서 「보류」는 별도 영역

**제가 한 것** — `할 일 / 진행중 / 검토요청 / 완료` 4열 + 하단에 「보류」 영역.

**왜** — 설계서 §6.1에 *"칸반은 보류를 제외한 4열"* 이라고 되어 있습니다. 보류를 열로 두면 카드가 거기 쌓여 시야를 가립니다.
