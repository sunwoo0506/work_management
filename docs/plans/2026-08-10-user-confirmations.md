### C-04. 3단계(AI)를 시작하려면 두 가지가 필요합니다 ⏸

**3단계만 남기고 4·5·7단계를 먼저 만들었습니다.** 아래 둘이 정해지면 3단계로 돌아갑니다.
저장 공간(문서 양식·문서·AI 대화)은 미리 만들어 뒀으니, 정해지면 화면만 붙이면 됩니다.

| | 무엇 | 왜 필요한가 |
|---|---|---|
| **OQ-08** | **주기적으로 하는 행정 신고가 정확히 뭐뭐입니까?** | 문서 양식을 등록할 대상이 정해져야 초안 기능을 만들 수 있습니다 |
| **OQ-12** | **어느 AI 모델을 쓸까요?** | 공급자는 OpenAI로 정했지만 모델명이 미정입니다 |

**OQ-08에 필요한 것** — 신고 이름 · 주기 · 기한 · 필요 자료. 예를 들면:

```
부가세 신고    분기    분기 종료 후 25일    이카운트 매출·매입, 위하고 원장
원천세 신고    매월    다음 달 10일         급여대장
4대보험 신고   매월    다음 달 15일         급여대장, 입퇴사 내역
법인세 신고    연      3월 31일             재무제표
```

> 💡 **이건 2단계 「절차」에 바로 넣을 수도 있습니다.** 지금 절차로 등록해 두면 3단계에서 문서 양식만 붙이면 됩니다.

**OQ-12에 대한 제 의견** — 문서 초안과 절차 추출은 판단이 섞인 작업이라 상위 모델이 낫습니다. 예외 설명처럼 쉬운 일은 값싼 모델로 분리할 수 있게 `AI_MODEL`·`AI_MODEL_LIGHT` 두 개를 두겠습니다.

### C-09. 아직 안 써보신 화면 — 절차와 일지 🟡

업무·지시사항은 확인하셨습니다. **아직 한 번도 안 돌려본 것이 둘 남았습니다.**

| 탭 | 해볼 것 |
|---|---|
| **절차** | 「＋ 새 절차」 → 단계 2~3개 → **상태를 「확정」으로** → 「이번 회차 시작」 |
| | 시작하면 **업무가 자동으로 생깁니다** |
| | 단계를 체크하고 소요시간을 적은 뒤 「회차 완료」 |
| | 필수 단계를 일부러 건너뛰고 완료 → **예외 확인함**에 잡혀야 합니다 |
| **기록** | 「오늘 일지 열기」 → 이슈·내일 할 일 적고 **일부만 체크** → 「일지 확정」 |
| | 다음날 「오늘」 탭 **어제 이야기**에 뜨는지 |

**미리 알려드릴 것** — 절차는 **상태를 「확정」으로 바꿔야** 「절차 대기」에 뜹니다.
「초안」이면 안 뜹니다. 헷갈리시면 알려주세요, 기본값을 바꾸겠습니다.

> 💡 D-11(일일 현금표)처럼 **매일 하는 일**을 첫 절차로 만들어 보시면 감이 옵니다.

### C-06. 녹음 자동 전사는 못 만들었습니다 ⏸

**무슨 일이냐** — 「폰으로 녹음한 파일을 올리면 회의록이 된다」는 기능입니다.

**왜 못 만들었나** — **브라우저만으로는 안 됩니다.** 음성을 글로 바꾸는 일은 무거운 계산이라
컴퓨터에서 따로 도는 프로그램이 필요합니다. 이 툴은 브라우저에서만 도는 웹앱입니다.

**대신 이렇게 해뒀습니다** — 회의록 화면에서 **전사문을 붙여넣을 수 있게** 했습니다.
다른 도구로 전사한 글을 옮겨 담으면 됩니다.

**나중에 붙일 수 있는 방법 세 가지**

| | 방법 | 대가 |
|---|---|---|
| ① | 컴퓨터에서 도는 작은 프로그램을 따로 만든다 | 켜 두어야 돌아감. 설치가 필요 |
| ② | OpenAI 전사 API 를 쓴다 | 녹음 파일이 밖으로 나감. **민감 회의는 못 씀** |
| ③ | 붙여넣기로 계속 쓴다 (지금) | 손이 한 번 더 감 |

> 설계서 §14에 **OQ-14**로 올려 두었습니다. 어느 쪽이 좋으실지 알려주시면 그때 만들겠습니다.
> 회생·인사 회의는 ②를 쓰면 안 됩니다.

### C-07. 회생 건을 눈에 띄게 할까요 🟡

**상황** — 설계 모형에서는 회생(D-12)만 **주황색**으로 칠해 두셨습니다.

**제가 한 것** — 파란색으로 통일했습니다.

**왜** — 작업 규칙(`CLAUDE.md`)에 *"파란색이 유일한 강조색이다. 두 번째 강조색을 만들지 않는다"*고
적혀 있습니다. 규칙과 모형이 부딪혀서 규칙을 따랐습니다.

**확인 필요** — 회생 건이 눈에 띄어야 하면 알려주세요. 두 방법이 있습니다.

| | 방법 | 대가 |
|---|---|---|
| ① | 규칙에 예외를 하나 더 두고 주황색 사용 | 색이 늘어나면 강조가 흐려집니다 |
| ② | 색 대신 **표시(⚑)나 굵기**로 구분 | 규칙을 안 깨고 눈에 띕니다 |

> 답이 없으면 지금대로 둡니다. 급한 건 아닙니다.

### C-08. 업무 시작일이 비어 있습니다 🟡

**상황** — 넣어 드린 업무 46건에 **기한만 있고 시작일이 없습니다.**

**왜 안 넣었나** — 자료에 시작일이 없었습니다. **없는 걸 지어내면 그게 진짜인 줄 알게 됩니다.**

**지금 어떻게 보이나** — 「오늘」 화면 타임라인에서 막대가 전부 **「시작 미정」**으로 뜨고

**하실 것** — 「계획」 탭에서 요일별로 배치하시거나, 업무 수정에서 시작일을 넣으시면
막대가 제대로 그려집니다. **급하게 다 채우실 필요는 없습니다** — 계획을 세우면서 하나씩.

## 🟡 제가 정했지만 알아두셔야 하는 것

### D-01. 시드를 마이그레이션이 아니라 앱에서 만든다

**문제** — 업체와 지시사항에는 `user_id`가 필요한데, 마이그레이션 SQL에 특정 사용자 UUID를 박으면 **다른 환경에서 안 돌아갑니다.**

**제가 한 것** — 로그인 후 앱이 최초 진입 시 **업체가 하나도 없으면 자동으로 만들도록** 했습니다. 지시사항 13건도 그때 같이 들어갑니다.

**대가** — 시드 내용이 SQL이 아니라 TypeScript 파일(`frontend/src/features/seed/`)에 있습니다. 나중에 바꾸려면 그 파일을 고칩니다.

---

### D-02. `activity` 기록을 앱에서 남긴다 (DB 트리거 아님)

**선택지** — ① 앱 코드에서 남긴다 ② DB 트리거로 자동으로 남긴다

**제가 한 것** — ①. 업무 상태를 바꿀 때 등 **의미 있는 순간에만** 남깁니다.

**왜** — 트리거는 모든 변경을 남겨서 노이즈가 많고, "무엇이 의미 있는 변경인가"는 업무 규칙이라 DB보다 앱이 알기 좋습니다. 대신 앱에서 빠뜨리면 기록이 안 남습니다.

---

### D-03. 업무 순서는 사람이 직접 바꾸지 않는다

**제가 한 것** — `sort_order` 컬럼은 만들어 뒀지만 **화면에서 쓰지 않습니다.** 정렬은 `domain/sort.ts`가 정한 순서(일정 상태 → 중요도 → 기한)를 따릅니다.

**왜** — 설계서 §6.9의 정렬 규칙이 이미 있고, 사람이 손으로 옮긴 순서와 자동 정렬이 부딪히면 어느 쪽이 맞는지 알 수 없습니다. 필요해지면 나중에 켭니다.

---

### D-04. 「이슈로 공유」 버튼은 자리만 만들어 뒀다

**제가 한 것** — 업무 상세에 버튼을 두되, 누르면 *"6단계에서 연결됩니다"* 안내만 뜹니다.

**왜** — 연동 계약서가 초안 상태입니다. 지금 만들면 계약이 바뀔 때 다시 만들어야 합니다.

---

### D-05. 칸반에서 「보류」는 별도 영역

**제가 한 것** — `할 일 / 진행중 / 검토요청 / 완료` 4열 + 하단에 「보류」 영역.

**왜** — 설계서 §6.1에 *"칸반은 보류를 제외한 4열"* 이라고 되어 있습니다. 보류를 열로 두면 카드가 거기 쌓여 시야를 가립니다.
