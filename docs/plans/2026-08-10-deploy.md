# 배포 — Cloudflare Pages

## 왜 Vercel이 아니라 Cloudflare인가

둘 다 이 앱을 잘 올립니다. 화면만 있고 서버가 없는 구조(정적 사이트)라서 기술적으로는 차이가 거의 없습니다. **갈린 지점은 딱 하나입니다.**

| | Vercel 무료(Hobby) | **Cloudflare Pages 무료** |
|---|---|---|
| **회사 업무에 써도 되나** | ❌ **안 됩니다.** 무료 요금제는 개인·비상업용 전용입니다 | ✅ **됩니다.** 상업적 이용 제한이 없습니다 |
| 회사에 쓰려면 | 유료 전환 필요 (인당 월 20달러) | 그대로 무료 |
| 로그인 벽을 앞에 세울 수 있나 | 유료부터 | ✅ 무료 (Cloudflare Access, 50명까지) |
| 속도·안정성 | 충분 | 충분 |

**이건 회사 업무 도구입니다.** Vercel 무료로 올리면 약관 위반이고, 지키려면 돈이 듭니다. Cloudflare는 같은 걸 무료로 허용합니다. 그래서 Cloudflare로 정했습니다.

> 덤 — Cloudflare는 **사이트 앞에 로그인 벽을 하나 더 세우는 기능(Access)이 무료**입니다. 지금도 이 앱에 로그인이 있지만, "주소를 아는 사람은 로그인 화면까지는 볼 수 있다"가 걸리면 그 앞을 통째로 막을 수 있습니다.

## 준비된 것

| 파일 | 하는 일 |
|---|---|
| `frontend/public/_redirects` | 주소창에 `/work`를 직접 치거나 새로고침해도 화면이 뜨게 합니다 |
| `frontend/public/_headers` | 남의 사이트가 이 화면을 자기 페이지 안에 못 넣게 막고, 검색엔진에 안 잡히게 합니다 |

**빌드 산출물에 위험한 키가 없는 것을 확인했습니다.**

- 브라우저에 들어간 열쇠는 `anon`(공개용) 하나뿐입니다 — 직접 열어서 확인했습니다
- `service_role`(전체 권한 마스터 키)은 없습니다
- 데이터 보호는 **로그인 + RLS**(남의 데이터가 안 보이게 막는 장치)가 합니다

## ⚠ 남은 한 가지 — Supabase에 주소 등록 (안 하면 로그인이 안 됩니다)

**이건 제가 못 합니다.** Supabase 열쇠가 Windows 자격 증명 저장소에 있어서
제가 읽을 수 없습니다. 대신 **직접 하시면 30초**입니다.

로그인 메일의 링크가 어디로 돌아와야 하는지를 Supabase가 알아야 합니다.
지금은 그 목록에 새 주소가 없어서, 메일 링크를 눌러도 `localhost`로 갑니다.

1. https://supabase.com/dashboard/project/mpcphuyvffsccsmrocwu/auth/url-configuration
2. **Site URL** 칸에 →

```
https://work-management-dbh.pages.dev
```

3. **Redirect URLs** 에 아래 둘을 **각각 추가** →

```
https://work-management-dbh.pages.dev/**
http://localhost:5173/**
```

4. **Save**

`localhost`를 같이 두는 이유 — 안 두면 컴퓨터에서 개발할 때 로그인이 안 됩니다.
끝의 `/**` 는 "그 아래 어느 화면으로 돌아와도 된다"는 뜻입니다.

## 그 다음부터 — 고친 걸 다시 올릴 때

```
! cd frontend && npm run build && npx wrangler pages deploy dist --project-name=work-management --branch=main --commit-dirty=true
```

`--branch=main` 을 빼면 **본 주소가 아니라 미리보기 주소로만** 올라갑니다.
`--commit-dirty=true` 는 "커밋 안 한 변경이 있어도 그냥 올려라"입니다.

## 나중에 생각할 것

| | 무엇 | 언제 |
|---|---|---|
| **로그인 벽 추가** | Cloudflare Access로 사이트 앞을 통째로 막기 | 주소가 노출되는 게 걸릴 때 |
| **자동 배포** | GitHub에 올리면 알아서 배포되게 연결 | 배포가 잦아질 때 |
| **주소 바꾸기** | 회사 도메인 연결 | 필요해지면 |

**자동 배포를 지금 안 하는 이유** — 그러려면 Cloudflare 쪽에도 Supabase 열쇠를 넣어야 합니다. 지금은 컴퓨터에서 빌드해서 결과물만 올리므로 열쇠가 한 군데(내 컴퓨터의 `.env.local`)에만 있습니다. 두는 곳이 적을수록 안전합니다.
