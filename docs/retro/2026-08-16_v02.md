## 🛠 작업 상세

### 1. 화면 폭에 따라 배치가 바뀌게 (반응형)

- **무엇을:** 화면이 좁으면 배치가 바뀌도록 20여 곳을 고쳤습니다.

  | 넓은 화면 (노트북 · 탭 가로) | 좁은 화면 (폰 · 탭 세로) |
  |---|---|
  | 왼쪽에 메뉴 기둥 | **위쪽에 가로 메뉴 줄** (옆으로 밀어 봅니다) |
  | 본문 + 오른쪽 곁칸 | **세로로 쌓임** |
  | 업무판 4칸 | **2칸** |
  | 입력칸 2~4개가 한 줄 | **한 줄에 하나** |
  | 주간 계획표 7칸 | 7칸 그대로, **옆으로 밀어 봄** |

- **왜:** 확인해 보니 **화면 폭을 신경 쓰는 설정이 저장소 전체에 0건**이었습니다. 왼쪽 메뉴가 248px,
  오른쪽 곁칸이 320px로 못 박혀 있어서, 폰(가로 약 390px)에서는 본문이 들어갈 자리가 없었습니다.
  지금까지 노트북에서만 쓴다는 전제로 만들었기 때문입니다.
- **결과:** 폰에서도 화면이 안 눌립니다. 갤럭시탭은 **가로로 눕히면 노트북과 같은 배치**,
  세로로 세우면 폰과 같은 배치가 됩니다.

### 2. 좁은 화면의 메뉴는 「줄인 것」이 아니라 「다른 물건」으로

- **무엇을:** 메뉴를 한 벌로 만들어 크기만 줄이지 않고, **두 벌로 나눠 썼습니다.**
  좁은 화면용(위쪽 가로 줄)과 넓은 화면용(왼쪽 기둥)이 각각 있습니다.
- **왜:** 세로 기둥과 가로 줄은 같은 것의 크고 작은 모습이 아닙니다. 좁은 화면에서는
  「오늘 한눈에」 요약을 접어야 하고, 빠른 입력 버튼 세 개 중 하나만 남겨야 하고,
  메뉴는 옆으로 밀어 보게 해야 합니다. **억지로 한 벌로 만들면 양쪽 다 어정쩡해집니다.**
- **결과:** 폰에서 메뉴가 한 줄에 들어가고, 노트북 화면은 **전혀 바뀌지 않았습니다.**

### 3. 표는 줄이지 않고 옆으로 밀게

- **무엇을:** 지시사항 목록표와 주간 계획표는 좁은 화면에서도 칸을 줄이지 않고,
  대신 손가락으로 옆으로 밀어 보게 했습니다.
- **왜:** 칸을 억지로 줄이면 제목이 한 글자씩 끊겨 세로로 늘어섭니다. **읽을 수 없는 표는 표가 아닙니다.**
  요일 7칸도 마찬가지입니다.
- **결과:** 폰에서도 표가 표로 보입니다.

### 4. 민감 회의 잠금 해제

- **무엇을:** 「민감 회의」를 켜도 **받아쓰기가 그대로 동작**합니다. 전사문도 똑같이 저장됩니다.
  v01에서는 「민감」이 **잠그는 스위치**였는데, 이제 **표시**입니다.
- **왜:** 사용자 판단입니다 — 회의 종류를 구분하지 말고 둘 다 되게 해 달라, 보안은 나중에 보자.
- **결과:** 회생·인사 회의도 자동 회의록이 됩니다. 대신 그 회의의 음성과 글이 밖으로 나갑니다.
  **표시를 남긴 것이 이 작업의 핵심입니다** — 아래 이슈 2번 참고.

## 😵 어려웠던 점 & 해결

### 🟡 1. 화면 대응을 한 줄도 안 해 뒀었습니다

- **상황:** *"갤럭시탭에서도 되나"* 를 확인하려고 화면 코드를 뒤졌습니다.
- **증상:** 화면 폭에 따라 배치를 바꾸는 설정이 **저장소 전체에 0건**이었습니다.
  왼쪽 메뉴 248px 고정, 오른쪽 곁칸 320px 고정. 폰에서는 본문 자리가 사실상 없습니다.
- **원인:** 「노트북에서 쓰는 도구」라는 전제가 **한 번도 글로 적히지 않은 채** 코드에만 있었습니다.
  아무도 반대하지 않았고, 아무도 확인하지 않았습니다.
- **해결:** 기준선을 1024px 하나로 잡았습니다. 그보다 좁으면 좁은 화면 배치입니다.
  기준을 여러 개 두면 어디서 무엇이 바뀌는지 아무도 못 외웁니다.
- **남은 문제:** ⚠️ **실제 기기에서 눈으로 확인하지 못했습니다.** 코드로만 맞췄습니다.
  로그인이 메일 링크 방식이라 자동으로 화면을 띄워 찍어 볼 수가 없었습니다.
  그래서 **배포부터 하고 사용자에게 확인을 부탁**하는 순서가 됐습니다.

### 🟡 2. 같은 날 만든 잠금을 같은 날 풀었습니다

- **상황:** v01에서 「민감 회의는 받아쓰기를 잠근다」를 만들고, 설계서·작업규칙·기획서·확인메모
  **네 문서에 그렇게 적었습니다.** 몇 시간 뒤 사용자가 풀어 달라고 하셨습니다.
- **증상:** 코드 한 줄(잠금)만 지우면 **문서 네 개가 코드와 어긋난 채 남습니다.**
  나중에 그 문서를 읽는 사람은 「잠긴다」고 믿습니다.
- **원인:** 규칙을 여러 문서에 적어 두면 바꿀 때도 여러 군데를 고쳐야 합니다.
  이건 구조상 피할 수 없습니다 — 규칙은 코드 옆에도, 설계서에도, 사용자 안내에도 있어야 합니다.
- **해결:** 네 곳을 전부 고치되, **지우지 않고 「무엇이 어떻게 바뀌었는지」를 적었습니다.**
  기획서에는 맨 위에 「이 문서의 이 부분은 뒤집혔다」는 안내를 달고 본문은 그대로 뒀습니다.
  판단이 바뀐 것도 기록이기 때문입니다.
- **남은 문제:** ⚠️ **지금 회생·인사 회의의 음성과 전사문이 밖으로 나갑니다.**
  이건 「고쳤다」가 아니라 「알고 미뤘다」입니다. 설계서 **OQ-16**에 되돌리는 세 가지 방법을 적어 뒀습니다.

### 🟡 3. 「민감」 표시를 없앨 뻔했습니다

- **상황:** 잠금을 푸는 가장 간단한 방법은 **체크박스를 통째로 지우는 것**이었습니다.
  막지도 않을 표시를 왜 두나 싶었습니다.
- **증상:** 지웠다면 지금부터 쌓이는 회의록에 **회생 회의와 일반 회의가 구분 없이 섞입니다.**
- **원인:** 「기능」과 「기록」을 같은 것으로 봤기 때문입니다. 체크박스는 **동작을 바꾸는 스위치**이기도 하지만
  **그 회의가 어떤 성격이었나를 남기는 기록**이기도 합니다. 앞의 역할이 사라져도 뒤의 역할은 남습니다.
- **해결:** 표시를 남기고, 화면 설명을 *"표시만 해 둡니다"* 로 바꿨습니다.
  작업규칙(CLAUDE.md)에는 **"표시를 없애지 않는다"** 를 명시했습니다.
- **남은 문제:** 사용자가 그 체크를 안 누르면 표시가 안 남습니다. **막지 않는 표시는 잊히기 쉽습니다.**
  확인 메모에 "체크는 꼭 켜 주세요"를 적어 뒀지만, 구조적으로 보장되지는 않습니다.

### 🔴 4. 고쳐 놓고 배포를 안 해서, 사용자가 예전 화면을 보고 계셨습니다

- **상황:** 화면 대응을 다 끝내고 *"폰에서 열어봐 주세요"* 라고 말씀드렸습니다.
- **증상:** 사용자가 폰 화면을 찍어 보내주셨는데 **고치기 전 그대로**였습니다.
  왼쪽 메뉴가 화면을 거의 다 차지하고, 「오늘」이 한 글자씩 세로로 늘어서 있었습니다.
  *"사이드바 회의록 추가 버튼은 작동도 안 해"* 라고도 하셨습니다.
- **원인:** **만든 것과 올라가 있는 것이 다릅니다.** 이 앱은 GitHub 연결 자동 배포가 아니라
  **제 컴퓨터에서 빌드해 결과물만 올리는 방식**입니다. 그 마지막 한 걸음을 안 밟았습니다.
  「빌드 통과 · 테스트 통과」를 보고 **끝났다고 착각한 것**이 진짜 원인입니다.
  그 둘은 *"코드가 말이 된다"* 는 뜻이지 *"사용자가 볼 수 있다"* 는 뜻이 아닙니다.
- **해결:** 배포했습니다. 「회의록 추가 버튼이 안 눌린다」도 같은 이유로 보입니다 —
  버튼은 눌렸지만 **본문이 화면 밖으로 밀려 있어서** 아무 일도 안 일어난 것처럼 보인 것입니다.
  좁은 화면에서 그 버튼이 아예 없어지지 않도록 위쪽 줄에도 남겨 두었습니다.
- **남은 문제:** ⚠️ **화면을 바꿨으면 배포까지가 한 묶음**인데, 그걸 강제하는 장치가 없습니다.
  다음에도 같은 실수가 납니다.

## 🔀 갈림길에서 무엇을 왜 골랐나

### 좁은 화면에서 메뉴를 어떻게 할까

| | |
|---|---|
| **고른 것** | **위쪽 가로 줄** (옆으로 미는 방식) |
| 버린 것 | ① 햄버거 버튼 → 서랍이 옆에서 나옴 ② 아래쪽 탭바 |
| **결정적 이유** | **한 번 눌러서 이동**할 수 있습니다. 서랍 방식은 「열고 → 고르고 → 닫고」 세 동작이 됩니다. 메뉴가 6개뿐이라 한 줄에 밀어 넣을 수 있었습니다 |
| **치른 대가** | 메뉴가 6개를 넘어가면 오른쪽 것이 화면 밖으로 나가 **안 보입니다.** 밀면 나오지만 밀 수 있다는 걸 모를 수 있습니다 |

### 민감 회의를 어떻게 다룰까

| | |
|---|---|
| **고른 것** | **막지 않는다. 표시만 남긴다** (사용자 판단) |
| 버린 것 | ① v01처럼 잠근다 ② 체크박스를 아예 없앤다 |
| **결정적 이유** | 사용자가 정하신 것입니다. 그리고 지금 단계에서는 **쓰이지 않는 도구보다 쓰이는 도구가 낫습니다** — 회생 회의를 손으로 적게 하면 결국 아무 기록도 안 남습니다 |
| **치른 대가** | **회생·인사 회의 내용이 외부 서버 세 곳을 거칩니다** (브라우저 제조사 · Supabase · AI 공급자). 이건 나중에 정리해야 하는 빚입니다 — OQ-16 |
