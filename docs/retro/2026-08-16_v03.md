## 🛠 작업 상세

### 1. 「녹음해서 받아쓰기」 — 두 번째 길

- **무엇을:** 브라우저가 **녹음만** 하고, 그 소리를 서버로 보내 글로 바꾸는 길을 만들었습니다.
  화면 위쪽에서 두 방식 중 하나를 고릅니다.

  | | ⚡ 브라우저 | 🎧 녹음 |
  |---|---|---|
  | 누가 받아쓰나 | 브라우저 제조사 | **우리 서버 → AI 공급자** |
  | 글자가 보이는 때 | 말하는 즉시 | **45초쯤 뒤 한 덩어리씩** |
  | 폰·태블릿 | 잘 안 됨 | **됨** |
  | 사내 용어 미리 알려주기 | ✕ | **○** |
  | 요금 | 0원 | 소리 길이만큼 |

- **왜:** 브라우저 내장 받아쓰기는 **원래 「검색어 한마디 받아쓰기」용**입니다. 한 시간짜리
  회의를 듣는 물건이 아닙니다. 폰에서는 아예 없는 브라우저(삼성 인터넷)도 있습니다.
  **녹음은 어느 폰에서나 되는 기본 기능**이라, 브라우저가 하는 일을 녹음까지로만 줄이면
  기기를 안 가리게 됩니다.
- **결과:** 폰·갤럭시탭에서 받아쓰기가 됩니다. 그리고 **사내 용어를 미리 알려 줄 수 있게
  됐습니다** — 이건 브라우저 쪽으로는 불가능했던 일이라, 정확도에서 오히려 앞섭니다.

### 2. 45초로 끊어 보냅니다

- **무엇을:** 한 시간을 통째로 두지 않고 45초짜리 토막으로 끊어, 토막마다 서버로 보냅니다.
- **왜:** 통째로 두면 **회의가 끝날 때까지 글자를 한 자도 못 봅니다.** 그리고 한 시간짜리
  소리 파일은 한 번에 보내기에 너무 큽니다. 끊어 보내면 ① 회의 중에 쌓이는 게 보이고
  ② 중간에 끊겨도 그때까지 받은 글은 남습니다.
- **결과:** 45초쯤 늦게, 한 덩어리씩 글이 올라옵니다.

### 3. 「지금 듣고 있다」를 눈에 보이게

- **무엇을:** 두 가지를 넣었습니다.

  | 방식 | 무엇이 보이나 |
  |---|---|
  | 🎧 녹음 | **소리 막대.** 말하면 차오릅니다. 마이크가 잡고 있다는 증거입니다 |
  | ⚡ 브라우저 | **단계 표시.** 켜짐 → 소리 들어오는 중 → 말소리 감지됨 → 글자 받아쓰는 중 |

- **왜:** *"듣는 건지 모르겠어"* 가 이번 일의 절반이었습니다. 화면에는 「듣는 중」만 떠 있고
  아무 일도 안 일어나니, **고장인지 마이크가 먼 건지 알 수가 없었습니다.**
- **결과:** 어디서 막혔는지가 보입니다. 「말소리 감지됨」까지 갔는데 글자가 안 나오면
  **마이크 문제가 아니라 받아쓰기 문제**라는 뜻입니다. 그때는 화면이 녹음 방식으로
  바꾸라고 권합니다.

### 4. 기기를 보고 알아서 고릅니다

- **무엇을:** 손가락으로 쓰는 기기(폰·태블릿)면 **처음부터 「🎧 녹음」**으로 열립니다.
  노트북이면 「⚡ 브라우저」입니다.
- **왜:** 사용자가 폰에서 겪은 일을 다음 사람이 또 겪으면 안 됩니다. **잘 안 되는 것을
  기본값으로 두면 안 됩니다.** 노트북에서는 브라우저 쪽이 공짜에 즉시라 더 낫습니다.
- **결과:** 폰에서 열면 그냥 됩니다. 고르는 줄은 남겨 뒀으니 바꿀 수도 있습니다.

## 😵 어려웠던 점 & 해결

### 🔴 1. 녹음 토막을 「이어지는 조각」으로 받으면 두 번째부터 못 읽습니다

- **상황:** 녹음을 45초마다 잘라 보내려고 했습니다. 브라우저 녹음기에는 *"몇 초마다 조각을
  주세요"* 라고 시키는 기능이 있어서, 처음에는 그걸 쓰려고 했습니다.
- **증상:** 그렇게 하면 **첫 조각만 소리 파일로 열리고, 두 번째부터는 안 열립니다.**
- **원인:** 소리 파일에는 맨 앞에 **「이 파일은 이런 형식이다」를 적은 머리말**이 있습니다.
  이어지는 조각에는 그게 없습니다. 조각은 **파일이 아니라 파일의 일부**입니다.
- **해결:** 조각을 받는 대신 **45초마다 녹음을 멈췄다가 곧바로 다시 시작**합니다.
  그러면 토막 하나하나가 **머리말이 붙은 완전한 파일**이 됩니다.
- **남은 문제:** 멈췄다 켜는 그 찰나에 나온 말은 놓칠 수 있습니다. 아주 짧지만 0은 아닙니다.

### 🟡 2. 안드로이드에서는 「자꾸 끊긴다」가 정상 동작이었습니다

- **상황:** 브라우저 받아쓰기가 끊기면 다시 켜도록 만들어 뒀고, **10초에 8번 넘게 끊기면
  고장으로 보고 멈추게** 해 뒀습니다.
- **증상:** 그런데 안드로이드는 **한 마디 받아쓸 때마다 끊습니다.** 그게 원래 동작입니다.
  잘 되고 있는데도 「계속 끊깁니다」라고 판정해 멈춰 버릴 수 있었습니다.
- **원인:** 「끊김」을 전부 같은 것으로 봤기 때문입니다. **글자를 내놓고 끊긴 것**과
  **아무것도 못 내놓고 끊긴 것**은 완전히 다릅니다.
- **해결:** **글자가 한 번이라도 나오면 그동안의 끊김 셈을 지웁니다.** 이제 「고장」은
  *"연달아 여덟 번 끊겼는데 그 사이 글자가 한 자도 없었다"* 일 때만 뜹니다.
- **남은 문제:** 없음. 다만 이 판정 기준은 **실제 폰에서 돌려봐야** 맞는지 압니다.

### 🟡 3. 녹음 토막을 넘기는 함수가 옛것으로 굳을 뻔했습니다

- **상황:** 토막이 완성되면 「이 토막을 처리해라」라는 함수를 부르게 만들었습니다.
- **증상:** 그런데 녹음기는 **처음 받은 함수를 계속 붙들고 있습니다.** 회의 중에 화면이
  다시 그려지면(글자가 올라올 때마다 그렇습니다) 그 함수는 새것으로 바뀌는데,
  녹음기는 옛것을 부릅니다. **나중 토막이 화면에 안 붙습니다.**
- **원인:** 오래 도는 장치(녹음기)와 자주 바뀌는 것(화면 함수)을 직접 묶었기 때문입니다.
- **해결:** 함수를 **그릇에 담아** 두고, 녹음기는 그 그릇을 봅니다. 그릇 안의 내용은
  화면이 바뀔 때마다 새것으로 갈아 끼웁니다.
- **남은 문제:** 없음. 다만 오래 도는 장치를 만들 때마다 나오는 함정이라 적어 둡니다.

### 🟡 4. 저장 공간이 새 값을 거부할 뻔했습니다

- **상황:** 회의록마다 「어느 길로 받아썼나」를 남기는데, 값을 두 가지(직접입력·실시간받아쓰기)로
  **못 박아** 두었습니다.
- **증상:** 세 번째 값(녹음전사)을 넣으면 저장이 **거부됩니다.**
- **원인:** v01에서 값의 목록을 좁게 잡았습니다. 그때는 두 가지뿐이었으니 틀린 판단은
  아니었지만, **하루 만에 세 번째가 생겼습니다.**
- **해결:** 목록을 넓히는 것을 저장 공간에 반영했습니다(마이그레이션). 그 제약에 붙은
  이름을 코드가 **찾아서** 지우고 새로 걸게 했습니다 — 이름을 손으로 적으면 다르면 실패합니다.
- **남은 문제:** 값 목록을 좁게 못 박는 방식은 **바꿀 때마다 저장 공간을 손봐야** 합니다.
  대신 잘못된 값이 절대 안 들어옵니다. 그 값어치가 더 크다고 봅니다.

## 🔀 갈림길에서 무엇을 왜 골랐나

### 폰에서 받아쓰게 하려면

| | |
|---|---|
| **고른 것** | **녹음해서 서버가 받아쓰기** (두 길을 나란히 두고 기기에 따라 자동 선택) |
| 버린 것 | ① 브라우저 받아쓰기를 더 고쳐 본다 ② 브라우저 쪽을 버리고 녹음만 남긴다 ③ 내 PC에서 도는 프로그램 |
| **결정적 이유** | ①은 **고칠 수 있는 게 아닙니다** — 브라우저에 그 기능이 없으면 끝입니다. ②는 노트북에서 공짜로 즉시 되는 것을 버리는 셈입니다. ③은 회의 때 PC를 켜 둬야 합니다 |
| **치른 대가** | 길이 두 개가 되어 **관리할 것이 늘었습니다.** 그리고 녹음 쪽은 **요금이 붙습니다** |

### 토막을 얼마로 끊을까

**45초.** 짧으면 자주 보이지만 호출이 늘고, 길면 뜸하게 보입니다.
한 시간 회의면 80번쯤 부릅니다. 실제로 써 보고 조정할 값입니다.

### 요금을 얼마나 들여도 되나

| | |
|---|---|
| **고른 것** | **`whisper-1`** (분당 $0.006 = 1시간 510원) |
| 버린 것 | `gpt-4o-mini-transcribe` (분당 $0.003 = 1시간 255원, 절반) |
| **결정적 이유** | 한국어 회의에서 어느 쪽이 잘 받아쓰는지 **아직 모릅니다.** 처음부터 싼 쪽을 골랐다가 못 알아들으면 「녹음 방식은 별로다」로 결론이 나 버립니다. **먼저 잘 되는지 보고, 그다음에 아낍니다** |
| **치른 대가** | 두 배 비쌉니다. 다만 월 5,000원 대 2,500원이라 **판단을 그르칠 만한 차이가 아닙니다** |

> 모델명은 코드에 없습니다. 환경변수 한 줄로 바꿉니다 — 비교해 보고 정하면 됩니다.

### 회의 중 자동 요약

**여전히 안 합니다** (v01에서 정한 대로). 녹음 쪽은 이미 45초마다 서버를 부르고 있어서,
요약까지 얹으면 요금이 두 배가 됩니다.

## 📚 오늘 배운 것

| 주제 | 한 줄 |
|---|---|
| **안 되는 것을 기본값으로 두지 않는다** | 폰에서 안 되는 방식이 폰에서 기본이었습니다. 기기를 보고 고르게 했습니다 |
| **「되고 있다」를 보여 주는 것도 기능이다** | 글자가 안 나오는 것보다 *"듣는 건지 모르겠다"* 가 더 나빴습니다 |
| **조각은 파일이 아니다** | 소리 파일은 머리말이 있어야 열립니다. 이어지는 조각에는 그게 없습니다 |
| **같아 보이는 실패를 한 덩어리로 묶지 않는다** | 「글자를 내놓고 끊긴 것」과 「아무것도 못 내놓고 끊긴 것」은 다릅니다 |
| **오래 도는 장치는 바깥 함수를 붙들면 안 된다** | 그릇(ref)에 담아 두고 그릇을 보게 해야 최신 것을 부릅니다 |
| **사용자의 짐작을 흘려듣지 않는다** | *"브라우저 녹음기라서 그런 거 같은데"* 가 정확히 원인이었습니다 |
| **시간으로 매기는 요금은 금액을 적어 준다** | 설계서 원칙은 「금액을 적지 않는다」이지만, 토큰과 달리 **시간 과금은 사용자가 스스로 가늠할 수 없습니다.** 대신 확인한 날짜와 모델명을 함께 적었습니다 |
