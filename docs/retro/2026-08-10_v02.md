## 3. 🛠 작업 상세

### 3-1. 절차와 실행이력 (2단계)

- **무엇을:** 「이런 일은 이렇게 한다」를 적는 **절차**와, 그 절차를 이번에 실제로 돌린 **회차** 기록을 만들었습니다. 절차에는 언제 시작하는지(트리거)·무엇이 필요한지·단계·**판단 기준**·결과물을 적습니다.
- **왜:** 이게 없으면 6개월을 써도 남는 게 업무 제목과 완료일뿐입니다. 나중에 AI가 이어받을 때 배울 것이 없습니다.
- **결과:** 절차에서 「이번 회차 시작」을 누르면 **업무가 자동으로 생깁니다.** 단계를 체크하면서 걸린 시간을 적을 수 있습니다.

> **반복업무를 따로 만들지 않았습니다.** 매일·매주 하는 일은 「주기가 정해진 절차」일 뿐입니다. 담으려던 저장 공간 2개가 사라졌습니다.

### 3-2. 주기 계산을 손으로 짰습니다

- **무엇을:** 「매월 10일」·「분기 종료 후 25일」 같은 주기가 **언제 돌아오는지** 계산하는 부분을 따로 떼어 만들었습니다.
- **왜:** 이건 판단이 아니라 계산입니다. 규칙 문서에 *"계산으로 되는 것은 AI에 맡기지 않는다"* 고 적혀 있습니다. 이유는 셋입니다 — **검사할 수 있고, 돈이 안 들고, AI가 멈춰도 동작합니다.**
- **결과:** 2월에 31일이 없는 것, 분기 끝이 언제인지 같은 걸 자동으로 처리합니다. 검사 항목이 붙어 있어서 나중에 고쳐도 망가진 걸 바로 압니다.

### 3-3. 업무일지와 「어제 이야기」 (4단계)

- **무엇을:** 하루 끝에 오늘 있었던 일·막힌 것·내일 할 일을 적습니다. **확정하면 그날 진행한 업무가 굳습니다.**
- **왜:** 나중에 업무를 고쳐도 지난 일지는 안 변해야 합니다. 연말에 *"3월에 뭐 했더라"* 를 되짚을 때 그때 기록이 그대로 있어야 합니다.
- **결과:** 어제 적은 「막힌 것」이 오늘 아침 화면 맨 위에 뜹니다. **「내일 할 일」 중 체크한 것만** 업무가 됩니다 — 전부 자동으로 넘기면 안 할 일까지 쌓입니다.

### 3-4. 예외를 툴이 잡습니다 (5단계)

- **무엇을:** 절차대로 안 됐을 때를 **여섯 가지 규칙으로 자동 탐지**합니다. 사람은 「맞다/아니다」만 확인합니다.

| | 무엇을 잡나 | 몇 번째 회차부터 |
|---|---|---|
| ① | 필수 단계를 건너뜀 | 1회차부터 |
| ② | 순서를 바꿔서 함 | 1회차부터 |
| ③ | 걸린 시간이 평소의 2배 또는 절반 | **3회차부터** |
| ④ | 나와야 할 결과물이 안 나옴 | 1회차부터 |
| ⑤ | AI에게 맡긴 단계에 사람이 끼어듦 | 2회차부터 |
| ⑥ | 절차에 없는 단계를 함 | 1회차부터 |

- **왜:** *"예외도 사람이 적지 않는다. 툴이 탐지하고 사람은 확인만 한다"* 가 규칙입니다. 사람에게 적으라고 하면 안 적습니다.
- **결과:** 회차를 완료하면 예외가 자동으로 「확인함」에 쌓입니다. **③번이 3회차부터인 이유** — 표본이 2개면 「평소」가 뭔지 알 수 없어서 아무 회차나 이상하다고 합니다.

### 3-5. 리포트 (5단계)

- **무엇을:** 주간·월간·연간으로 무엇을 했는지 집계합니다. 영역별·중요도별로 나눠 보여줍니다.
- **왜:** 밖으로 나가는 보고서가 아닙니다. **본인 모니터링과 연말 성과평가 자료**입니다.
- **결과:** 「확정」을 누르면 그 시점 숫자가 굳습니다. 숫자가 설명 못 하는 것을 적는 **서술** 칸을 따로 뒀습니다 — 성과평가에서 실제로 쓰이는 건 이 부분입니다.

### 3-6. 계획·기준·기록 (7단계)

- **무엇을:** 여섯 가지를 한 번에 만들었습니다.

| 어디 | 무엇 |
|---|---|
| **계획** | 주간/월간 계획 (목표 · 요일별 배치 · 회고), 마일스톤, 일정 |
| **기준** | 인수인계, 연락처, 설정(업무영역·사내 용어집) |
| **기록** | 회의록, 전화메모 |

- **왜 「계획」과 「리포트」를 둘 다 두나:** 방향이 반대입니다. **계획은 앞을 보고, 리포트는 뒤를 봅니다.** 같은 주 경계(월~일)를 쓰기 때문에 나란히 놓으면 「계획대로 됐나」가 보입니다.
- **결과:** 요일별 칸에 업무를 놓을 수 있고, **「아직 안 놓은 것」이 비어야 한 주가 배치된 것**입니다.

> **배치할 때 기한을 안 건드립니다.** 기한은 남이 정한 약속이고, 배치일은 내가 정하는 것입니다. 둘을 섞으면 「언제까지」와 「언제 할지」를 구분할 수 없게 됩니다.

### 3-7. 사내 용어집을 지금 만들어 뒀습니다

- **무엇을:** 「설정」에 사내 용어집 칸을 만들었습니다. 아직 아무 데서도 안 씁니다.
- **왜:** **3단계에서 AI가 문서를 쓸 때 이걸 봅니다.** 그때 만들면 늦습니다 — 6개월치 용어를 한 번에 떠올려야 하는데 그게 안 됩니다. 지금부터 생각날 때마다 쌓아 두는 게 낫습니다.
- **결과:** 쓰이는 곳이 없어도 만들어 뒀습니다. 이런 「미리 만들어 두는 것」은 보통 낭비지만, **채우는 데 시간이 걸리는 것**은 예외입니다.

## 4. 😵 어려웠던 점 & 해결

### 🔴 4-1. 같은 화면을 두 번 켜는 바람에 기본 데이터가 두 벌 생겼습니다

- **상황:** 사용자가 처음 로그인했을 때 업체와 지시사항이 자동으로 만들어지게 해 뒀습니다.
- **증상:** 업체 「제우스」가 **2건**, 지시사항이 **26건**(13의 두 배) 들어갔습니다. 만들어진 시각 차이가 **52밀리초**였습니다.
- **원인:** 개발 중에는 화면이 두 번 켜집니다(실수를 미리 찾아내려고 일부러 그렇게 돕니다). 중복을 막는 표시를 **화면 안에** 뒀는데, 화면이 다시 켜지면서 그 표시도 같이 초기화됐습니다. 두 번 다 "업체가 없네"를 보고 각각 만든 겁니다.
- **해결:** 두 겹으로 막았습니다. ① 표시를 **화면 밖**으로 옮겨 다시 켜져도 안 지워지게 했고, ② **저장소 자체에** 「같은 이름의 업체는 하나만」이라는 제약을 걸었습니다. **②가 중요합니다** — 앱 코드가 또 실수해도 저장소가 거부합니다.
- **남은 문제:** ⚠️ **이미 만들어진 중복 1건은 아직 남아 있습니다.** 지우는 명령이 안전장치에 걸려서 우회하지 않고 확인을 기다리는 중입니다. 확인 메모 C-00에 방법을 적어 뒀습니다.

### 🔴 4-2. 검사 도구가 「화면 파일에서 화면이 아닌 것을 꺼내지 말라」고 막았습니다

- **상황:** 화면 파일 안에 편의 기능을 하나 같이 넣어 뒀습니다.
- **증상:** 코드 검사 도구가 두 번 같은 지적을 했습니다 — 화면 파일은 화면만 내보내야 한다는 규칙입니다.
- **원인:** 개발 중 화면을 자동으로 갈아끼우는 장치가 **파일 단위로** 동작합니다. 한 파일에 화면과 화면 아닌 것이 섞이면 갈아끼울 때 상태가 어긋납니다.
- **해결:** 편의 기능을 별도 파일로 뺐습니다.
- **남은 문제:** 파일 수가 늘었습니다. 대신 **어디에 무엇이 있는지가 이름으로 드러납니다.**

### 🔴 4-3. 저장소에 물어본 결과를 다루는 방식이 달랐습니다

- **상황:** 저장소에 자료를 넣고 그 결과로 다음 일을 하는 코드를 세 군데 짰습니다.
- **증상:** 검사 도구가 *"이건 약속한 형태가 아니다"* 라며 막았습니다.
- **원인:** 저장소 라이브러리가 돌려주는 것이 **일반적인 「기다릴 수 있는 것」과 미묘하게 달랐습니다.** 겉보기엔 같아 보여서 눈치채기 어렵습니다.
- **해결:** 세 군데를 「기다린다」는 뜻이 코드에 그대로 드러나는 방식으로 다시 썼습니다. 결과적으로 **읽기도 더 쉬워졌습니다.**
- **남은 문제:** 없습니다. 다만 이 라이브러리를 쓸 때는 이 방식을 기본으로 삼는 게 낫습니다.

### 🟡 4-4. 녹음을 글로 바꾸는 기능을 못 만들었습니다

- **상황:** 7단계에 「폰 녹음을 올리면 회의록이 된다」가 있었습니다.
- **증상:** 만들려고 보니 **브라우저 안에서는 할 수 없는 일**이었습니다.
- **원인:** 음성을 글로 바꾸는 건 계산이 아주 무겁습니다. 이 툴은 **브라우저에서만 도는 웹앱**이고, 그런 무거운 계산을 돌릴 자리가 없습니다.
- **해결:** 전사문을 **붙여넣을 수 있게** 했습니다. 다른 도구로 글로 바꾼 것을 옮겨 담으면 회의록이 됩니다. 나머지 기능(안건·결정사항·민감 표시)은 다 동작합니다.
- **남은 문제:** ⚠️ 세 갈래가 남았습니다 — ① 컴퓨터에서 따로 도는 작은 프로그램을 만든다 ② 전사 서비스에 파일을 보낸다 ③ 붙여넣기로 계속 쓴다. **②는 회생·인사 회의에 못 씁니다** — 녹음이 밖으로 나갑니다. 확인 메모 C-06과 설계서 OQ-14에 적었습니다.

### 🟡 4-5. 3단계(AI)를 건너뛰어야 했습니다

- **상황:** 순서대로면 2단계 다음이 3단계입니다.
- **증상:** 시작하려니 두 가지가 안 정해져 있었습니다 — **어떤 행정 신고 문서를 다루는지**, **어느 AI 모델을 쓰는지**.
- **원인:** 이 둘은 코드로 정할 수 있는 게 아닙니다. 실제 업무를 아는 사람만 답할 수 있습니다.
- **해결:** **멈추지 않고 4·5·7단계를 먼저 만들었습니다.** 대신 3단계가 쓸 **저장 공간은 미리 만들어 뒀습니다** — 문서 양식, 문서(초안+확정본), AI 대화 기록.
- **남은 문제:** 그릇만 있고 화면이 없습니다. 확인 메모 C-04에 무엇이 필요한지 적었습니다.

## 5. 🔀 갈림길에서 무엇을 왜 골랐나

### 5-1. 3단계를 건너뛴다 vs 기다린다

| | |
|---|---|
| **고른 것** | 건너뛰고 4·5·7단계 먼저 |
| **버린 것** | 3단계가 풀릴 때까지 대기 |
| **결정적 이유** | 사용자가 *"내가 확인해야 할 게 있으면 메모로 남기고 넘어가면서 진행해줘"* 라고 했습니다. 그리고 **AI가 없어도 나머지가 다 돌아가야 한다**는 게 원래 설계입니다 |
| **치른 대가** | 단계 번호와 만든 순서가 어긋났습니다. 나중에 문서를 읽는 사람이 헷갈릴 수 있습니다 |

### 5-2. 예외 탐지를 AI로 vs 규칙으로

| | |
|---|---|
| **고른 것** | 여섯 가지 규칙을 손으로 짬 |
| **버린 것** | AI에게 회차 기록을 주고 "이상한 것 찾아줘" |
| **결정적 이유** | **검사할 수 있고, 돈이 안 들고, AI가 멈춰도 동작합니다.** AI는 나중에 「왜 그랬는지 설명」만 얹습니다 |
| **치른 대가** | 규칙에 없는 종류의 이상은 못 잡습니다. 대신 잡은 것은 **왜 잡혔는지 항상 설명됩니다** |

### 5-3. 리포트를 실시간 계산 vs 굳혀서 저장

| | |
|---|---|
| **고른 것** | 확정 시점 숫자를 통째로 저장 |
| **버린 것** | 볼 때마다 다시 계산 |
| **결정적 이유** | 나중에 업무를 고치면 지난 리포트가 같이 변합니다. **연말 성과평가 자료가 그러면 안 됩니다** |
| **치른 대가** | 저장 공간을 더 씁니다. 그리고 확정 뒤에 실수를 발견해도 그 리포트는 못 고칩니다 — 이건 의도한 것입니다 |

### 5-4. 배치일과 기한을 하나로 vs 따로

| | |
|---|---|
| **고른 것** | 따로 |
| **버린 것** | 기한 하나로 둘 다 표현 |
| **결정적 이유** | **기한은 남이 정한 약속이고, 배치일은 내가 정하는 것**입니다. 하나로 두면 "금요일까지인데 수요일에 하기로 했다"를 표현할 수 없습니다 |
| **치른 대가** | 사용자가 두 날짜의 차이를 알아야 합니다. 화면에 설명을 붙여 뒀습니다 |

### ⚠️ 아직 안 풀린 구조적 문제

**① 저쪽 서비스와 같은 것을 두 번 만들고 있을 수 있습니다.** 경영관리서비스 설계서에 이쪽과 똑같은 업무 관리 기능이 들어 있습니다. **저쪽 설계가 굳으면 중복이 확정됩니다.** 연동 계약서를 써서 넘길 준비는 해 뒀습니다.

**② 저장소가 OneDrive 폴더 안에 있습니다.** 작업 기록 폴더가 한 번 통째로 사라진 적이 있습니다(회고 `2026-08-09_v01` 이슈 1). 오늘도 문서 폴더가 잠깐 안 보이는 일이 있었습니다. **근본 해결은 저장소를 OneDrive 밖으로 옮기는 것**인데, 아직 안 했습니다.

**③ 샘플 데이터가 섞여 있습니다.** 사용자가 *"나중에 한꺼번에 지울게"* 라고 해서 그대로 뒀습니다. 실제로 쓰기 시작하기 전에 정리가 필요합니다.

### 일부러 안 한 것

- **「이슈로 공유」 버튼** — 자리만 있고 누르면 안내만 뜹니다. 연동 계약이 굳기 전에 만들면 다시 만들어야 합니다
- **업무 순서 직접 바꾸기** — 자동 정렬 규칙이 이미 있는데 손으로 옮긴 순서와 부딪히면 어느 쪽이 맞는지 알 수 없습니다
- **반복 규칙 자동 해석** — 일정의 「매주 월」은 사람이 읽는 문장으로만 둡니다. 자동 생성까지 하려면 규칙 해석 장치가 필요한데, 지금 필요한 건 「이번 주에 뭐가 있더라」를 잊지 않는 것뿐입니다

## 7. 📚 오늘 배운 것

| 주제 | 한 줄 |
|---|---|
| **중복은 저장소에서 막는다** | 앱 코드에서만 막으면 코드가 실수할 때 그대로 들어간다. 저장소에 제약을 걸면 앱이 실수해도 거부된다 |
| **화면이 두 번 켜지는 걸 전제로 짠다** | 개발 중에는 실수를 찾으려고 일부러 두 번 켠다. 「한 번만 실행」을 화면 안에 두면 안 된다 |
| **표본이 3개는 있어야 「평소」를 말할 수 있다** | 2개로 평균을 내면 아무 값이나 이상하다고 한다 |
| **미리 만들어 두는 게 옳은 경우가 있다** | 보통은 낭비지만, **채우는 데 시간이 걸리는 것**(용어집 같은)은 필요해진 시점에 만들면 늦다 |
| **못 하는 일은 빨리 인정하고 우회로를 낸다** | 녹음 전사는 브라우저가 못 한다. 붙여넣기로 열어 두니 나머지 기능은 다 살았다 |
| **막히면 멈추지 말고 순서를 바꾼다** | 3단계가 막혔다고 기다렸으면 오늘 네 단계가 안 나왔다. 대신 **왜 건너뛰었는지를 반드시 적어 둔다** |
